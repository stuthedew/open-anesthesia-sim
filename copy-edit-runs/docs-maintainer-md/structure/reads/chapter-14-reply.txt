- 947–951: what the tagging workflow does, and which cases fall to the owner. Facts: `.github/workflows/tag-release.yml` tags each release on the commit that cut it, once that commit reaches `main`. When a run fails, the session fixes the cause and starts a new run itself. Two cases are left to the owner (`PL-F23S`, `PL-S641`). While a release is untagged, `bin/docket release` refuses to cut the next one, and its refusal message names both cases.
- 953–954: case 1, GitHub refuses the session's run. The owner starts the run in either of two ways.
- 956–959: way 1, the GitHub web page. On the repository's page: **Actions**, then **tag-release** in the left sidebar, then **Run workflow** above the list of runs. Leave **Branch** on `main`, which the workflow requires, and click **Run workflow**. The log of the **tag** job ends with `Tagged VERSION and pushed it to origin.`
- 960–963: way 2, the script. Run `python3 tools/tag_release.py --apply` on the Mac, from a clone up to date with `main`. It tags with the owner's own credentials, because a tag that a session pushes is dropped without any error (`PL-N936`). It prints the same last line once `origin` holds the tag.
- 965–970: a third command, its source, and how to check the result. Facts: `gh workflow run tag-release.yml --ref main` starts the same run. GitHub's "Manually running a workflow" (https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow) gives both routes, read 2026-10-18. Check the result with `git ls-remote --tags origin refs/tags/VERSION`. It prints the tag when `origin` has it, and nothing when it does not.
- 972–981: case 2, `origin` already holds the tag on another commit. Facts: the run declines and tags nothing. Its log says `Declined: origin holds VERSION on COMMIT, not on its cut, CUT.` The owner decides which of the two commits is right. The cut is the commit that added the version's notes under `docs/releases/`. If the tag on `origin` is right, nothing needs to change. If it is wrong: first copy the line that `git ls-remote` prints, so the old commit is recorded. Then delete the tag with `git push origin --delete refs/tags/VERSION`, and start the run again by one of the ways above. To undo the deletion, run `git push origin COMMIT:refs/tags/VERSION`.
