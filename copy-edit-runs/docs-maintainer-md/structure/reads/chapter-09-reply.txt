Outline:
- Row 658: heading "Bring a stale base in when you merge, with Update branch".
- Rows 660-665: why the update is yours.
  - Since 2026-09-23, `main` requires a pull request's branch to be up to date before it merges (`PL-6MW8`, after the third merge-skew instance).
  - Sessions deliberately leave a pull request behind `main` while it waits on you.
  - Each update re-runs CI in full, which takes two to five minutes.
  - An update made before you merge goes stale as soon as another pull request lands.
  - So you make the update once, when you come to merge.
- Rows 667-677, step 1: update the branch.
  - Open the pull request in the Mac's browser and scroll to the merge box at the bottom of the Conversation tab.
  - If it offers **Update branch**, click it. The button merges `main` into the branch.
  - Do not use **Update with rebase** from the dropdown, because it rewrites the branch's history under any session still working on it.
  - A "Merge branch 'main' into ..." commit appears and the checks restart.
  - If the box offers **Squash and merge** and no Update branch, the branch is current: merge it as the section above says, and stop.
  - If the pull request is a draft, leave it. The draft carries a session's claim and GitHub will not merge it. That session marks it ready when the claimed item closes or is blocked (`PL-H14W`).
- Rows 678-689, step 2: arm auto-merge.
  - If the box already says auto-merge is enabled, skip this step, because the update leaves it armed. The box says this on a captures-only pull request that a session armed.
  - Otherwise click **Enable auto-merge**, check that the message box holds the pull request's description, and click **Confirm auto-merge**.
  - Since 2026-10-03, `main`'s rule has **Do not allow bypassing the above settings** turned on (`PL-NXRJ`), so the checks and the up-to-date rule apply to you as to everyone else.
  - To merge past a broken CI, go to **Settings**, then **Branches**, then **Edit** beside the `main` rule. Untick the setting, click **Save changes**, merge, then tick it again the same way.
  - While the setting is off, a session will not merge a pull request that is already green and current. It hands that pull request to you.
- Rows 690-695, step 3: wait and check.
  - Come back in about five minutes. Success is the pull request marked **Merged**.
  - If another pull request landed first, `update-armed.yml` has brought `main` in again and the checks are running. Come back in another five minutes.
  - If the box still offers **Update branch**, the workflow could not update the branch, and its newest run under **Actions** says why. Click the button and come back in another five minutes.
- Rows 697-700: several pull requests ready at once.
  - Arm auto-merge on each and update just one.
  - When that one merges, `update-armed.yml` brings `main` into every other armed pull request that the merge left behind. That re-runs their checks, and the next to go green merges.
- Rows 702-708: switching auto-merge off holds a pull request back, and its session leaves it off.
  - GitHub names your account for every switch, including switches a session makes through its tools.
  - A session records each switch it makes as an `Auto-merge: off - <why>` trailer on its next commit.
  - `bin/docket arm` asks GitHub for the latest switch. If auto-merge is off and no commit since that switch carries the record, it holds the pull request.
  - The session then arms or merges the pull request only when you say so (`PL-8TPV`).
- Rows 710-716: a check fails after the update.
  - A failing check means the branch and the new `main` do not work together. That is merge skew, which the up-to-date setting now stops at the pull request instead of on `main`.
  - Leave auto-merge armed and ask a session to fix the branch. Auto-merge lands it once the fix is green.
  - The session's `bin/docket arm` tells it the same, so the session leaves your auto-merge armed.
  - If the box shows conflicts and no Update branch, do not use **Resolve conflicts**. Ask a session to merge `main` in and resolve them.
