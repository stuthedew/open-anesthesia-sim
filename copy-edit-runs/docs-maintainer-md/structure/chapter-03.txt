- 149-159: `delegable` is an offer, never an instruction. It is derived from `Item.delegability`. An item qualifies when it is `ready`, has no `safety` or `science` class, has no open decision, and has a `verify:` command that proves it done. Its `touches` must be declared and lie wholly outside `protected_paths` and `gate_paths`, where a directory holding one of those paths counts as inside. Each `touches` path outside `tests/` must be placed by `workflow_paths` or `product_paths`. The item's effort must be `S` or `M`. By design no field grants delegability; only `not-delegable:` withholds it. Declining the offer and running the strongest model is always available and never wrong. The flag makes the cheap case visible; it does not ask for it to be taken.
