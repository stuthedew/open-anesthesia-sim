Outline:
- 7413: heading, "Development rules for scientific milestones".
- 7415–7416: rule for the scientific core. Define the equations, units, assumptions and reference cases before changing the scientific core.
- 7417–7418: rule. Simulation code stays independent of the UI toolkit, wall-clock time, filesystem state and display dimensions.
- 7419–7420: rule. Model parameters are stored as validated data, with a schema version and provenance. Data files hold no executable equations.
- 7421–7422: rule. Results are deterministic for an identical initial state, identical events and identical time steps.
- 7423–7424: rule. Mass accounting and independent reference cases are release gates, not optional diagnostics.
- 7425–7427: rule for scoping. Keep each milestone narrow. A new idea stays in "the sections below" until it is promoted into a scoped release. An idea that is a task rather than a release goes in `docs/items/`.
- 7428–7439: rule. A milestone's Goal is frozen and dated at scoping.
  - It records the problem the release was taken on to solve, in the tense and state of the day it was scoped.
  - Closing items do not amend it.
  - What the milestone achieved is recorded in its Required scope and Definition of done, which is where a reader looking for the current state is sent.
  - Reason: rewriting a Goal into the past tense clause by clause leaves the section describing neither the problem nor the product. It also puts an edit to `ROADMAP.md` on the critical path of every closure.
  - History: `PL-DXQC` is why the rule is written down. Two of v0.4.0's three Goal bullets were fixed while the section still asserted them in the present tense. One had been stale for two releases. No convention existed to breach.
- 7440–7453: rule. An exclusion goes under `Explicitly out of scope`, never inside a `Required scope` bullet.
  - Mechanism: these two subsections are the only structures `bin/docket next` reads to decide membership.
  - It reads `Required scope` in full, because a milestone names what it covers in any grammar, so "(queue item PL-DHV7)" in the middle of a bullet counts.
  - Cost: an id named inside a scope bullet in order to exclude it is treated as scope.
  - History: `PL-NBCS` is why the rule is written down. A stage-3 exclusion in v0.4.0 put `PL-B9PY` into v0.4.0's `scope_ids`. While v0.4.0 was the anchor, `docket next` told every session, as a fact and naming the milestone, that Gate-1 work was what v0.4.0 was waiting on.
  - Enforcement: `tools/doc_check.py` fails when an id is named under both headings of one milestone. It gives an advisory where a scope bullet contains exclusion language.
