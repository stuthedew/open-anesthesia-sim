**How.**
- `vcs.subject_pull_request` reads both of GitHub's subject shapes and returns the number together with which shape named it. `Landing`, `FilingCommit` and `merged_pull_requests` read both. `doc_check`'s tag-span read and `pr_body_check`'s squash walk keep the squash shape alone, as before, by filtering on that flag instead of a pattern of their own. One behaviour moves: `Landing.pull_request` now names the pull request for a merge-commit landing, where `left_behind_check` used to fall back to the commit hash.
- `vcs.github_slug` parses a remote the way git does. A URL with a scheme goes through `urllib.parse`, so a token and a port fall away with the host. An scp-like remote is read as `[user@]host:path`. The host must be `github.com` and the path exactly `owner/name`.
- `vcs.github_token` reads `GH_TOKEN` before `GITHUB_TOKEN`, the order `gh help environment` documents.
- `pr_body_check.default_branch_ref` and `pr_title_check`'s `--base` default ask `vcs.default_base`. `left_behind_check` keeps its live `ls-remote --symref` read of the remote's default, and its docstring now says why: it compares the remote's tips and takes the default from the same answer, and on the master-only clone that read already named `master`.
