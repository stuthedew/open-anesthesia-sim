Before: the gate guard (`.claude/hooks/gate-status-guard.sh`) refused every gate followed by an `||` fallback, and said the fallback succeeds. That is false for a fallback that fails too, so `make check || exit 1`, `make check || false` and `make check || { echo red; exit 1; }`, each of which exits non-zero on a red tree, were refused and cost a retry.

After: those pass, and so does the same shape inside a loop, while every fallback that can exit 0 is still refused: `|| true`, `|| { echo red; exit; }` (the `exit` returns the status of the `echo`), `|| exit 0` and `|| exit 256`, `|| false; echo after`, `|| exit 1 | tail`, `( make check || exit 1 ); echo after`, and a piped loop ending `|| exit 1; done | tail`. The refusal of an `||` no longer asserts that the fallback succeeds: it says a fallback that succeeds replaces the gate's status and nothing shows this one fails too, and names `exit 1` and `false` as endings that would.

How: the walk reads the fallback's first and last command. `exit` with no argument as the first command, or `exit N` (N a literal that is not 0 modulo 256) first or last in a `{ }` or `( )` group run after a `;`, ends the shell running it. So the walk stops there, or resumes where that shell ends when it is a subshell: a `( )`, or a group, `if` or loop that is piped or backgrounded, which the pass already tracking `pipefail` now records for each group. A `false`, alone or last, hands the failure to whatever follows the fallback. Anything else (a variable, `return`, `! true`, a last command behind `&&` or `|`) is refused as before. Every exit the tests pin was measured in bash 5.2.21 first, and PL-KQ4Q's brief records the table. `docs/worker.md`, which told a worker every `|| ...` loses the status, now says which ones do.

Verified: `make check` green locally (4,962 tests), and `bin/docket verify --self PL-KQ4Q` accepts. The 13 new allowed cases fail against the old hook, and the 9 new refused ones pass under both. The self-audit first refused a rewritten assertion (`fallback succeeds` in the refusal of `|| true`); it still holds for that fallback, so it stays, beside the new one.
