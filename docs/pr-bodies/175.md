## PL-RWZV — the brief check tests for a literal marker

`marker not in item.body` was the whole completeness test, and it was wrong in
both directions: `**Why it matters, and why it is not new.**` was rejected on
wording and had to be flattened, while a heading with nothing under it passed
on structure.

`_section_text` now matches a heading at line start by its opening words and
returns what sits between it and the next heading-opened line — `None` when the
heading is absent, `""` when it is there and empty — so the two failures carry
different messages, because the fix for each is different.

The **first** matching heading is the one judged. This item's own file carried
the four-heading stub above its real brief, at `ready`; a rule accepting any
occurrence with text would have passed exactly that shape, which is the hole
rather than the fix. The stub is deleted here.

The rule was prototyped over all 241 item files before it was written: it flags
that one file's two empty sections and nothing else, and nothing newly reads as
missing, so no existing brief is rejected by the change.

The doc sweep then found a second reader — `render.py` kept `triage`'s own
literal-substring test over the same markers, so `triage` would have called a
stubbed brief complete a moment before `check` errored on it, against the
README's promise that the two cannot drift. Both now call `brief_gaps`.

## PL-3576 — the offered-item advisory read a partial flight answer

`check` was the seventh reader of the flight answer and the one `PL-S1P1` left
out. Its grooming advisories name whichever item `next` would offer; the
ranking excludes work already in flight; so a ref this checkout could not walk
can move that name, or empty the advisory, with nothing saying so.

The cause sat one level above the call site. `history`, `landed` and `closures`
are report types carrying their own `declined`; `offered` was a bare
`frozenset[str]`, which is the shape that cannot report a partial reading — the
argument `FlightReport`'s docstring already makes about its own ids. So
`plan.OfferedReport` carries the ids and the reason, `analyze` takes it in
place of the set, and the decline is recorded beside the other three rather
than appended by `cmd_check` after the fact. Cost: fourteen test call sites,
mechanically updated behind a helper.

The sentence is `render.format_unread`'s, the same one the other six readers
print, under the `Not checked` heading the brief identified. `check` joins the
test that enumerates those six, because that list is what would have caught the
omission.
