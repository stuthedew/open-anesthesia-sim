After: each pull request's body is recorded in the tree at `docs/pr-bodies/N.md` while the pull request is open, and the required `pr-title` job holds the merge until that file matches the body GitHub has, checking again on every edit. A file recovered after a merge says so, with `recovered:` giving the date it was fetched and `squash:` naming how the squash copy compares, and `make check` fails on a recovered file whose `commit:` is not on `main`'s first-parent line.

How:

- `tools/pr_body_check.py` gains three modes. `--record [N]` fetches the body and writes the record; for a merged pull request it writes a recovered header with `commit:`, `merged:`, `items:`, `subject:` and `squash:`. `--check` is the required step: it reads `PR_NUMBER` and `PR_BODY` from the environment and compares the body with the head's record, after normalising line endings and trailing whitespace. `--anchors` runs in `make check`. `--recover` writes the new recovered header, and `--compare` stays as a hand-run measurement of the drift before this rule.
- `.github/workflows/pr-title.yml` runs `--check` as a third step of the required job, with the body passed through `env:` rather than interpolated.
