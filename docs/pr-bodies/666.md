## What it does

`verify.command_paths` reads a `verify:` line for the paths it reads *as data*, clause by clause on `&&`, `||` and `;` outside quotes. `verify.items_reading` turns a set of changed paths into the open items those paths could have invalidated. `cmd_check` unions that with what `vcs.changed_items` already returned and hands the pair to `already_passing`.

**A clause's program is not a file it reads.** `python3 tools/doc_check.py check` and `bin/docket check` contribute nothing, while `uv run pytest tests/unit/test_x.py` contributes its argument. Without that split, the 54 open commands carrying the documentation gate would replay behind any edit to it, and none of them discriminates on it.

Position was the obvious rule for that split and is wrong twice over: the health clause comes last in real commands (`grep -rq … src/anesthesia_sim/data/ && python3 tools/doc_check.py check`), and 13 of the 168 open commands are a single clause whose whole discrimination is a pytest selector.

**Textual throughout, and it asks the filesystem nothing**, so a file the branch is *creating* matches — `PL-XH1D`'s `test -f CONTRIBUTING.md` broke on the branch that created the file, which existed nowhere in the tree the command was written against. Where a token cannot be classified the reader widens: a quoted span is scanned for paths, and a wrapped interpreter's script counts as read. A candidate is offered directory containment only where it carries a `/`, so `grep -q 'src' …` does not put its command behind every edit under `src/`.
