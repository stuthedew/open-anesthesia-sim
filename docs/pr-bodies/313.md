## The item was wrong about its own incident, and that decided the design

`PL-3D2M` was captured as *a pull request merged at a stale head* — GitHub squashing a head older than the branch's tip. That is not what happened, and the difference is not academic: it names a detector that cannot see this failure.

Checked against GitHub's record of #284: `head.sha` at merge was `7f87bf5`, its three commits were `dc03044` and two merges of `main`, and `main` holds all of it. The lost commit `9fee36c` is in none of them. #286, the recovery, says it outright — *"That pull request merged at its first commit, so the behavior change pushed to the same branch afterwards never landed."* The merge took the whole head; the push came at 01:17 against a merge at 01:16.

So the real failure is: **a pull request merges the head it was opened against, and a commit pushed to the same branch afterwards is merged by nothing.** No conflict, no red check, no advisory — and a `CLAUDE.md`-mandated behavior change quietly void.

The correction is kept in the item rather than quietly applied, because a later reader meeting the old title needs to know why it changed.

## That resolves the item's fork, and not on the argument it expected

The fork was *detect it from the branch refs, or check at merge time against the GitHub API*. Three measurements:

- **A merge-time check would see nothing.** GitHub freezes `refs/pull/<n>/head` when the pull request closes, so a commit pushed afterwards appears in no pull-request ref. Fetched all 311 pull refs (1.9 s) and compared each merged head against the commit that landed it: **0 discrepancies and 0 conflicts across all 204 merged pull requests.** `PL-SK88`'s argument — that `docket` must not learn about this harness — was never needed.
- **The branch ref is the only evidence, and it survives *because* of the failure.** Merged heads are deleted here (origin holds 2 branches against 311 pull requests), so an ordinary merged branch leaves no ref. A post-merge push recreates one. The ref that should not exist is the signal.
- **The discriminator is a branch split across the base.** Content partly on the base and partly not. A branch nobody merged has landed nothing; a branch merged whole never reaches the read. Against the one live branch: **0 landed, 17 outstanding** — the clean signature of work in progress, so the rule was silent on the only ref it had to be silent on.
