Before: when `claim` finds a claim of this branch's that was never pushed, it withdraws it in favour of another session's claim that is already published. It decided "published" by reading the rival's tracking ref, and no fetch here prunes. #1116 stopped `holdings` reading a tracking ref for a branch the remote has deleted, but a local branch of the same name is still read. There the check still found the deleted rival's claim "published" and withdrew this branch's claim with exit 3, so the item was left held by nobody a fresh clone can see.

After: the check reads the rival's branch from the same `git ls-remote --heads` listing the rest of `claim` uses. A branch the listing lacks carries no published claim, so nothing is withdrawn in its favour. Where the listing names a tip this clone has not fetched, git cannot say what that tip carries, so the tracking ref is read as before. A rival that pushed since the fetch therefore still withdraws the claim, which is the direction PL-ZLJ9 exists for.

How: `_on_copy` takes the command's `RemoteHeads` and asks `merge-base --is-ancestor` against the listed tip. Exit 0 or 1 is the answer, and anything else (128 for an unknown commit) means git could not say. `_displaced` passes the listing through. Three real-git tests in `test_claiming.py`: the rival's branch deleted on the remote, read through its tracking ref and through a local branch too (the second exits 3 on `main`), and a rival tip this clone has not fetched, which still withdraws.

Also filed: PL-20DL. `_published` reads an unfetched tip of this branch's own copy as "does not carry the claim", so under `--no-fetch` `claim` reports a published claim as local-only. Reproduced, and left for its own pull request.
