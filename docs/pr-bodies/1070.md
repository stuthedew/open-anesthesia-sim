Before: running `bin/docket yield` again after its push failed printed "has already ended; nothing written", exited 0 and pushed nothing. The yield stayed in that one checkout, and every other session still read the item as held until the lease ran out.

After: the rerun is the retry, as `claim`'s rerun already is. When the remote's tip does not carry the `Yield:` that ended a claim, the rerun goes to `_publish` again. It pushes where the remote has no copy of the branch. Where the remote has the branch, it leaves the yield local, exits 4 and names the push command, because a pull request may be armed there.

## PL-NNLM (yield rerun after a failed push)

**What changed.** `claiming.yield_claims` now collects the items whose claim a yield of this branch's has ended. When there is nothing new to write, it asks `_on_remote` once and finds each yield's commit with `_recorded(..., trailer="Yield")`, which generalises the `Claim:` lookup that function already did. Any yield the remote's tip does not carry goes to `_publish(made_now=False, command="yield")`. A comment in `_publish` that said a rerun pushes nothing now says a rerun retries.
