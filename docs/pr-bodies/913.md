## PL-Q89J: `docket next --oldest`

Every term `docket next` ranks on favours newer, more urgent or more central work, so an owed item that is none of those waits while new work keeps arriving above it. That is starvation, and the standard remedy in priority scheduling is aging. `--oldest` is aging's extreme form, pure age order, offered beside the plan rather than changing it (design ratified by the project owner 2026-09-22, over a `--debt` filter in the plan's own order).

### What it does

- **Order.** Longest-waiting first by `added:`, `P0` on top whatever its age, ties by band then id. Age is `--today` minus `added`, so no git read is needed.
- **Population.** What `next` could start, narrowed by lane and `--effort` first, less new work, which is a new `new_work_classes` setting (`feature`, `planning`). A debt class or `needs-decision` keeps an item owed, so `docket gate` and `--oldest` cannot disagree about one item.
- **Decisions apart.** Owed `needs-decision` items go on a line of their own, oldest first, and are never ranked.
- **Never silent about the plan.** Each pick carries the placement sentence `next` writes. That sentence now comes from `_placed`, a helper shared with `recommend`, which drops the "ranks on its band alone" clause that age makes false. The last line names the plan's own pick for the same lane and effort.

Two edge cases the brief left open, and how they were settled:

- A `P0` at `needs-decision` stays on top rather than moving to the decisions line, because the P0 floor is absolute.
- An item carrying both a new-work class and a debt class stays owed (`is_debt` wins). None exist in the store today; the rule keeps the two commands consistent.

### Plain `next` is byte-identical

`next`, `next product`, `next workflow`, `next --effort S`, `next product --effort M --limit 5`, `next --limit 10` and `digest` were captured with main's code and then diffed after the change, on the same store with `--today 2026-09-22 --no-git`. All seven are identical.
