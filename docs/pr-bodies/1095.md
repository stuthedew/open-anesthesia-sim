Before: docket's `checks.py` read a `verify:` command three ways. The admitted-shape rule used its own quote-aware `_shell_words`, while the prerequisite rule and the `-k` rule cut the command at every `&&`, including one inside quotes, and split each piece with `shlex`, one with operator splitting and one without. So a pytest run followed by a pipe was refused as a redundant second proof when the pipe was written `|tail` and left alone when it was written `| tail`; a quoted `&&` in an argument, such as `--junitxml='a&&b.xml'`, split the run and hid it from both rules; and a trailing `# comment` was dropped by the `-k` rule and read as paths to run by the other.

After: every rule in `checks.py` reads a command through `_shell_words` and gets the same clauses, so spacing, quoting and a trailing comment no longer change what a rule decides. Across the 1,355 `verify:` commands in the store, both pytest rules give exactly the answers they gave before. Two refusal messages now name the whole operator (`||` and `>&`) instead of its first character. PL-B5VZ is closed. PL-PVW2 stays open, `generator: live`: asking where else docket reads a `verify:` command found `verify.py`, which reads one with regexes of its own and `shlex.split`, and misses a real `bin/docket verify` behind an apostrophe inside double quotes. That is filed as PL-P7J7, and PL-PVW2's `verify:` gains that step's predicted test.

How: `_shell_words` now reads every operator by bash's longest-match table (`_OPERATORS`, so `||`, `>&` and `&>` are single operators), records the first thing the admitted shapes refuse instead of returning at it, and returns a `_Reading`: the command cut into `&&` clauses, each with its tokens and its text as written, plus that refusal. A `#` that starts a word ends the reading, as it does in bash. The prerequisite and `-k` rules read their clauses from it, `_shell_tokens` and `import shlex` are removed, and `verify_shape_refusal` returns the reading's refusal as before. Docket keeps its own reading rather than importing `.claude/hooks/shell_split.py`, because `bin/docket` puts only docket's own package on the path, and the hooks' words drop the quoting the admitted shapes need. `subprojects/docket/tests/test_checks.py` adds `test_a_verify_clause_is_read_one_way` (the name PL-PVW2's `verify:` predicted), which fails on `main`'s `checks.py` and passes here. `bin/docket verify --self PL-B5VZ` says ACCEPT, with `make check` passing (4,895 tests).
