## How it works

A release's cut is the commit that added `docs/releases/vX.Y.Z.md`, compared with its first parent. `docket.release` states that definition once (`CUT_FLAGS`, `cut_query`, `tag_commands`), and `docket.vcs` reads it (`find_cut`, `notes_added`).

**1. The printed tag line looks the cut up when it runs.** `release.md`, `bin/docket release`'s hand-off and its untagged warning all print these lines:

```
git fetch origin main
git tag -a v0.3.0 "$(git log --first-parent --diff-filter=A --format=%H origin/main -- docs/releases/v0.3.0.md)" -m "v0.3.0"
git push origin v0.3.0
```

- Run after another merge, the line still tags the cut.
- Run before the release merges, the lookup prints nothing and `git tag` refuses with `Failed to resolve ''`, so nothing is pushed.
- The untagged warning also names the commit the line will find from here, with its subject.

**2. `doc_check` reads each tag, never `HEAD`.**

- **Why not `HEAD`.** A branch that merged `main` after a release has its own merge commit, and that merge added the notes file compared with its first parent. Measured: a lookup from `HEAD` named the branch's merge `4308874b` instead of the cut `fe2046f7`.
- **The check.** A tag is on its cut when its own commit added its own notes file. One batched `git log --no-walk` answers that for every tag.
- **What it reports.** A tag off its cut is reported by name, together with the commit its own history says it belongs on, before any version error. Tags from before notes were written keep the version check alone.
- **Spans.** `_tag_spans` takes its cuts from the same read instead of from `HEAD`.
- **Shallow clones** are not declined. The oldest commit reads as adding every file, which can pass a misplaced tag but can never fail a correct one. Only naming the cut is withheld there.

`docs/ARCHITECTURE.md` and the docket README each summarise what the tag check compares. Both now include where a present tag points.
