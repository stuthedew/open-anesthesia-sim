The project owner reported the Start, Pause and Reset labels missing on `0.4.26+gd67e06df`, then isolated it: macOS Dark appearance only, and the text returns in Light.

## The mechanism

`RunView` built the three as bare `QPushButton`s with no stylesheet, so their labels came from Qt's palette `ButtonText` role. That role follows the **host appearance** — Qt 6.11's `QStyleHints.colorScheme` documentation states the palette "follows the system's default color scheme (also known as appearance), and changes when the system color scheme changes". Under macOS Dark it is near-white, while every surface this interface draws is a hard-coded light value. White label, white surface.

Confirmed by driving the palette rather than reading the source: with `ButtonText` `#FFFFFF` and `Button` `#323232`, a bare button rendered its box at `#454545` — the palette's value — and the same button carrying the new stylesheet rendered `#FFFFFF`. A walk of the whole widget tree found these three were the only text-bearing controls left undeclared; every label goes through `styled_label`, both selectors through `selector_stylesheet`, which exists for this reason and says so.

## The fix, in two rounds

**Round one** declared `:enabled` — PANEL fill, INK label, MUTED edge — and left the disabled state whole to the platform, on `PL-NGF7`'s decision of 2026-09-16 and WCAG 2.2 SC 1.4.3's exemption for text in an inactive component.

**Round two** followed the owner's screenshots of that build, which showed the *disabled* button still absent: Start while running, Pause while paused. That is the cost `PL-NGF7`'s case did not carry — an exemption from a contrast *minimum* is not a licence for a control to disappear, and under a dark host appearance the platform's disabled grey is the second. So the disabled label is declared at `MUTED`: **5.00:1 on `PANEL`**, above SC 1.4.3's 4.5:1 for normal text, so no exemption is claimed at all. That matters because SC 1.4.11's own inactive-component wording has never been readable from this container (`PL-JX0Z`).

The edge keeps `MUTED` in both states. `PANEL` on `BACKGROUND` is 1.07:1, so the border is what identifies the control, and a user-interface component needs SC 1.4.11's 3:1 — met at 4.65:1, where `GRIDLINE` would fail at 1.22:1. The states are not separated by colour alone: `_status_text` beside the row says "Running" or "Paused", and `dashboard_frame.transport` derives the enablement from the same flag.

Confirmed on the owner's hardware at `0.4.26+gb3d8c01a`, in both states.

## Considered and rejected

`QGuiApplication.styleHints().setColorScheme(Qt.ColorScheme.Light)` in `app/main.py` — one line, and it would have covered the chrome too. Qt 6.11's own documentation rules it out as the *guarantee*: "doing so is a hint to the system, and overriding the color scheme is not supported on all platforms." A legibility guarantee for the run controls cannot rest on a hint the toolkit says may be ignored. It remains worth deciding on its own merits, which is `PL-KRZW`.

## The guard was rebuilt, not deleted

`check_disabled_states_are_the_style_s` refused any authored disabled styling; its own error message said the correct response was to declare the colour and add a requirement. That is what happened, so it is now `check_authored_disabled_colours_are_measured`: a `:disabled` rule is admitted only from a function some requirement cites by name, and refused with what is owed anywhere else. `setPalette` stays refused outright, now with a reason the admission cannot reach — it replaces the whole `Disabled` group at once, so there is no pair a requirement could name. Two unit tests differ only in whether a requirement cites the enclosing function.

The general scope decision survives: every other disabled colour under `app/` is still the platform style's.

## Tests

The widget test is parametrized over both states and asserts the darkest drawn pixel is nearest that state's declared colour rather than the palette's white, with a bare button rendered beside each so neither can pass vacuously. The `RunView` test holds all three buttons to carrying both rules — the half a test of the helper alone would not catch. Each was run both ways: failing before the work, passing after.
