`PL-R7C0` is retired rather than repaired — the recommended option, agreed.
Reading the code sharpened the case rather than changing it, and two facts
decide it.

## Neither existing silence could ever have covered this

`check_tags` has two guards. It returns early on an **empty** tag set, and it
withholds the `absent` errors when `is_shallow` says the checkout is truncated.
The baseline branch reached neither — it `continue`d *before* the truncation
guard.

A full clone holding v0.3.0–v0.3.2 but not v0.3.3 is neither empty nor shallow.
That is not an exotic state: it is the ordinary condition of any checkout more
than one release old, because `git fetch origin <branch>` does not bring tags.
So the advisory was unguarded in exactly the place it was most likely to be
wrong — on the newest version, the one most recently tagged. It fired on a
correctly tagged repository and printed a `git tag` command for a tag that
already existed.

## Retiring loses nothing permanent

The baseline is **skipped, not forgiven**. The moment a newer release lands,
the old version falls through to `absent` and is reported as an **error** — and
that is precisely when an untagged release begins to cost anything, since `git
describe --contains` only fails once history has moved past the gap.

The reminder to tag also still arrives where the question is answerable:
`docket release` refuses to cut the next release while the previous one is
untagged, with the network available and the version in hand.

Option 1 from the item — decline, as the shallow case does — was rejected on
the evidence: it keys on the checkout holding no tags at all, and this checkout
held three, so it would not have caught the instance that produced the item.

## What changed

`tools/doc_check.py` no longer appends the baseline advisory. The `continue`
**stays** — without it the release being cut becomes an error and `make check`
goes red on every release branch, which is `PL-8HJ2`'s failure. The docstring
now records all three silences and why this one was added.

In `tests/unit/test_doc_check.py`, `test_the_release_being_cut_is_an_advisory_not_an_error`
becomes `test_the_release_being_cut_is_silent` and asserts both lists empty;
`test_the_advisory_pastes_the_tag_commands_rather_than_asking_for_a_tag` is
deleted along with the string it asserted. The silence's safety is covered by
`test_a_completed_release_with_no_tag_is_an_error`, which already asserted
exactly that and whose docstring now says so — a second test repeating it was
written and then removed as duplication rather than left in.
