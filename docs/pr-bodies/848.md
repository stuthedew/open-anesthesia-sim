## What this fixes

`branches_in_flight` cannot separate a live session from a branch nobody will merge, says so, and leaves the age to decide. One case is not the age's to decide: a branch whose every claimed item is closed **in its own copy**, with no pull request open on it, is finished work that has stalled — and it was reported to every session as `in flight ... do not start these again`, which is exactly backwards. `claude/hopeful-allen-tetrje` sat that way for three hours with two items at `status: done` and ten item files existing nowhere else, and surfaced only because the project owner asked whether the feature had been built.

## How it works

**The git half — `vcs.settled_branches`.** Per in-flight ref, read the ref's own copies of the items it claims and ask whether every one is `done` or `dropped`. Kept out of `branches_in_flight` for the reason `files_in_flight` is: that read is on the hot path of `next`, `show`, `list`, `triage` and the session-start digest, and this one is wanted by the command whose question it is.

**The forge half — supplied, never reached.** `docket` answers from a bare checkout with no network and knows nothing about GitHub, and it should stay that way; which forge a project uses is not a fact about its queue. So the caller passes a *callable* that names the branches with a pull request open, and `docket.toml`'s new `open_pull_requests_command` points at `tools/open_pull_requests.py`, which lives beside `tools/main_ci_status.py` for the same reason. `tools/pr_title_check.py` now shares that request instead of making its own, so the token, the timeout and the every-failure-is-a-skip rule have one spelling.

**The cheap half decides whether the expensive one runs.** The callable is invoked only where reading the branches' own item files found a candidate — on a normal day, none — so `flight` reaches the network on no run at all until a branch actually finishes. Measured here: 0.70 s with the lookup configured, 0.70 s with `--no-remote`.

**Silence never reads as a clean answer.** `None` from the lookup — no token, no network, a forge that refused, no command configured — travels into `SettledReport.asked`, and the wording changes with it: `every item closed, and no pull request is open for it` when the forge answered, `every item closed` plus a line saying the rest went unread when it did not. A listing that came back at the page limit declines too, because a truncated listing cannot say a particular branch is absent while looking exactly like an answer that can. `flight --no-remote` asks for the unasked reading outright.

**What it does not say.** The section says nothing is being worked there and stops. Nothing in a checkout can say whether the work is reviewed, correct or ready, and a row a hurried reader could take for a merge recommendation would be a worse failure than the one this fixes. A test asserts the report never contains `safe to merge` or `ready to merge`.

**What it does not change.** The ids stay in flight for `docket next`: the work exists on a branch, and offering it again would have a second session redo what is already written. Only the row moves.
