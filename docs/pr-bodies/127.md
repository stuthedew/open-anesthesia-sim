## What landed

A `PreToolUse` hook on `Edit|Write|MultiEdit|NotebookEdit` runs `bin/docket branch --brief --if-stale` once per session, behind a marker keyed on the session id the hook is handed. The first edit is where a discussion becomes implementation, which is where the answer is wanted.

`--if-stale` is the new flag: say nothing unless the branch is behind. It is what makes a hook that speaks unasked bearable — "your base has not moved" is not worth interrupting an edit for. It fetches, which is also why the marker matters: per-edit would be a worse tax than the conflict it prevents.

**Two properties I checked against the current hooks documentation before writing the hook, not after** — both are the kind that look fine in a terminal and fail silently in place:

1. **A `PreToolUse` hook's plain stdout reaches the debug log and nothing the session can read.** A hook that echoed the line would have been a no-op. The line travels as `additionalContext` inside `hookSpecificOutput`, escaped by `json.dumps` because the text carries backticks, quotes and newlines.
2. **The JSON deliberately carries no `permissionDecision`.** Sending `allow` would auto-approve the very edit the hook is attached to — one key away from a permission grant nobody asked for. A test asserts that key stays absent.
