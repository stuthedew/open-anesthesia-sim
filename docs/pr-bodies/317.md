## The fix

The content split still selects candidates; a second condition now decides. **The branch must carry a commit none of whose paths reached the base at all.**

A commit partly landed is a commit the merge took *and merged* — the squash wrote it against a base that had moved underneath. A commit wholly absent is one nothing took. Ten paths touched and seven landed is silent; #284's dropped commit, every path outstanding, still reports.

The reported paths narrow to those commits' own, so a file the base merged differently is no longer offered for recovery, and `format_orphaned` prints each commit's paths under it rather than the branch's after the last one — which read as though they belonged to it.

The population a measurement covered is part of what it measured. The claim is qualified everywhere it appears — `vcs.orphaned`'s docstring and `subprojects/docket/README.md`.

## What is still wrong, deliberately

A commit pushed after the merge that happens to leave one file in a state the base has held reads as partly landed and goes unreported. Silence is this check's expensive direction everywhere else; the trade is taken only because the alternative was firing in every session.

`PL-VV4D` is filed for the test that admits no heuristic: the branch tip against the frozen `refs/pull/<n>/head`, which is exact — equal or an ancestor means nothing was left behind, a descendant names exactly the commits that were — but which makes the check GitHub-specific and so belongs in `tools/` rather than in `docket` (`PL-SK88`). That is a design decision, not a fix, so it is recorded rather than taken.
