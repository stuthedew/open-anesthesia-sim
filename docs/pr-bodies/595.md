## The defect

none of them was the audit. The only mention of the command a session met on
that path was `CLAUDE.md`'s fix-now rule naming the bare `bin/docket verify` —
the *delegated* mode, which REJECTs a correct close-out on four guards that fire
by construction. `PL-69JZ` fixed that in code in `#496`; the documented
procedure still led every session into it, so the defect survived its own fix
wherever a session followed the skill rather than `subprojects/docket/README.md`.

`grep -- '--self' .claude/skills/docket/SKILL.md CLAUDE.md` returned nothing
before this branch.

## What changed

Step 5 was `Re-run make check`. The audit **replaces** it rather than joining
it, and that is the one design decision here worth reading:

- `docket verify` runs `config.check_command` itself — `project_check` in
  `subprojects/docket/src/docket/verify.py:830`, with `check_command` defaulting
  to `make check` in `config.py:91`. A sixth step would have every close-out
  prove the tree twice, which is the cost the skill's own `verify:` section
  names as how a reviewer learns to skip a command.
- The safe-deletion clause is that a `REJECT` which stopped early ran *neither*
  the item's command nor `make check`. `verify_item` returns early on a missing
  `verify:` command or an empty diff, and `verify`/`verify_batch` append
  `project_check` only when it did not. The step says so, so the deletion cannot
  be read as a weakening.

The step also states what `--self` does **not** relax: the four commission
checks still print, as `NOTE`, naming every path, and the four integrity checks
stay absolute. A session may re-scope its own commission; it may not weaken what
measures it, and it may not skip the test. A closing line sends a reviewer of
somebody else's commissioned branch to the bare command.
