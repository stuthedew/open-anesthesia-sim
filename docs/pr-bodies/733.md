Closes the `model-capability-routing` feature. The project owner asked for a cheaper-model recommendation on clear-cut items, and specified the asymmetry it must have: err toward the strongest model whenever there is any question, and accept missing safe items rather than risk taking an unsafe one cheaply.

## The classification already existed; the recommendation did not print it

`Item.delegability` has decided this from the store all along — `ready`, no `safety` or `science` class, no open decision, a `verify:` command that proves it done, `touches` declared and wholly outside `protected_paths` and `gate_paths`, and `S` or `M` effort. It is derived rather than stored, and there is deliberately no field that grants it, so no session can mark its own work eligible.

`render._marks` prints `delegable` from it, so `docket list` and `docket delegable` both answered the question. `docket next` and the session-start digest — the two surfaces anyone actually reads when picking work — did not. 141 of 325 open items qualified, so 43% of the queue was carrying an answer that never reached the recommendation.

`recommend()` now takes `protected_paths`/`gate_paths` the way it already took `workflow_paths`/`generator_paths`, `Recommendation` carries the answer the way it already carried `scoped_to` and `generator`, and `format_digest` forwards both lists to `_marks`. A caller threading nothing still offers nothing: the fail-closed default is reached from the caller's end too.

## The tool names no model; `docs/maintainer.md` does

`.claude/rules/expert-review.md` asks for the instance rather than the rule, and a model name is a dated instance — so `next` prints `a cheaper model may take this` and the owner's notes resolve which one, with the date and what falsifies it. Both flags were unresolvable before this: the file named no model at either end.

- **Strongest, as of 2026-09-19: Claude Fable 5.1**, confirmed by the owner the same day as stronger than Opus (`PL-13PB`).
- **`delegable`, as of 2026-09-19: Claude Sonnet 5** — one named tier, not a choice between two (`PL-9FNV`). Naming Sonnet *or* Haiku would put the per-item judgment back at the moment of reading, which is what the stated asymmetry exists to remove. Recorded as this session's reading of the owner's preference rather than their own words, so it is the line to correct first if the reading is wrong.

Three checkable facts decide Sonnet over Haiku, none of them a preference:

1. Haiku 4.5 is a generation behind the Claude 5 family.
2. Its context window is 200K against 1M, leaving ~50K of headroom against `CLAUDE.md`'s 150,000-token handoff budget.
3. It does not take the effort parameter, so `docs/maintainer.md`'s own instruction to open apparatus sessions at `high` cannot be honoured on it.

Sonnet also already captures 75% of the largest saving available at first-party rates ($2/$10 per 1M against Opus 5's $5/$25 and Haiku 4.5's $1/$5).

## `opusplan` is no longer the recommended default

Verified against https://code.claude.com/docs/en/model-config on 2026-09-19 (`PL-V8QG`, which required the docs be read rather than recalled): the mode plans with `opus` and executes with `sonnet`, the split is fixed to those families, and no equivalent pairs a non-Opus strong model with a cheap one. So on the current lineup it plans one tier below the strongest model, which is what the section's own rule asks for. Its execution half is `sonnet`, which is the tier now named for `delegable` — the cheap end of both splits agrees.
