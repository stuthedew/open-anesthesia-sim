`tools/doc_check.py` read any quotation after `see` or `under`, or before `above` or `below`, as a section citation, and hard-failed when no heading carried that name. So a correct sentence quoting what a command printed - `See "docket check: 0 errors" for what a clean run prints.` - failed `make check`, and the only repair on offer was to reword prose that was not wrong. This closes PL-YSMV (the doc_check false-citation item).

## How it works now

- **The hard gate reads the section mark, and only the mark.** `CITATION_RE` matches `see § "X"`, `under § "X"`, `§ "X" above` and `§ "X" below`. A stale one still fails `make check`, exactly as before. A quotation without the mark is not a citation to this gate, whatever words surround it.
- **Unmarked citations of a real heading get an advisory, not silence.** `UNMARKED_CITATION_RE` reads the old positions without the mark and reports only where the quotation names a heading. It prints the `§` form to write. That is a fact about the tree: the quotation *is* a section citation. A quotation naming no heading may be output, a UI label or a figure, and gets nothing. This is the asymmetry `tools/possessive_section_check.py` already uses. It is an advisory rather than an error because the position is still wording: a quotation that merely coincides with a heading's name is told to take a mark it does not need.
- **Three smaller false refusals of this same check are fixed on the way.** Fences and code spans are read as literals. `TYPOGRAPHY` is folded when a title is compared, so a title quoted with an em dash resolves against a heading written with a hyphen. A cited file named just before the quotation, as in `` `docs/MODEL.md` under "Known limitations" ``, is left to `QUOTED_SOURCE_RE`, which already checks it by containment.

## Why seven documents changed

The documents held 147 citations written the old, unmarked way. Narrowing the gate without touching them would have dropped all 147 from checking silently. So a script inserted `§ ` before each quotation the new advisory named: 103 in `docs/MODEL.md`, 37 in `ROADMAP.md`, and 7 across five other documents. A character-level comparison against the base confirms **every change in those files is one `§ ` inserted immediately before a `"`**. Nothing else moved, and no value, equation or clinical statement in `docs/MODEL.md` changed. Three doc-qualified citations were deliberately left alone, since a `§` there would break the containment match that checks them.

## What is left, and where

This is the wording half of PL-GPJ7's citation gate (the generator head for hard gates that recognise a claim by wording). PL-YSMV is a member of PL-GPJ7, which the Projects trial (PL-NZC0) reserves in Stream A. It was worked here because the project owner named it directly. Reading **every** bare `§ "X"` stays PL-GPJ7's. On this tree that would find 7 unresolvable: PL-QQCD's 2 stale citations (a renamed baseline heading and a renamed validation-test heading) and 5 that cite an outside source's section (Yasuda 1991's "Materials and Methods" twice, the Gas Man workbook, Boumphrey and Marshall 2011, the Blender manual).
