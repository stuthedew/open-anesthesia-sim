After: each of those passes, and so do `command -- set`, the two nested spellings (`command builtin set`, `builtin command set`) and `FOO=1 command set`. `command -v set`, `builtin -p set`, `exec set`, `timeout 5 set` and `/usr/bin/command set` are still refused, because none of them runs `set` in this shell.

`command` and `builtin` run a builtin in the shell itself (`help command`, `help builtin`), so the `set` they run holds for the pipe after it: in bash 5.2.21, `false | true; echo $?` prints 1 after every spelling that now passes and 0 after every one still refused. The guard read a command's head through `shell_split.command_words`, which does not step past `command`, and `PL-TRMN` had kept the pipefail reader from reading past any wrapper, which is right for `timeout` and wrong for `command`.

How: `.claude/hooks/shell_split.py` gains `builtin_words`, which reads past a bare `command` and a bare `builtin` and nothing else, and `sets_pipefail` in `gate-status-guard.sh` reads the head through it. `command`'s options are read by the grammar `WRAPPERS` already holds for it, through `_run_by`, which now takes the table of grammars it reads by; `builtin` gets a grammar with no options, so anything but `--` stops it, as bash refuses it. A `command` named by path is a program and is not read past.
