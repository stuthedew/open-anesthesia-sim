GitHub deletes a head branch only when that branch's own pull request merges, and a session cannot delete a branch at all (`docs/worker.md` § "Ref operations a session cannot perform"). So every hand-off between sessions, every session that ended before opening a pull request, and every pull request closed unmerged left its branch behind: 14 by 2026-09-26. The project owner asked for this to stop, and for the cleanup to be a one-time thing (`PL-X8SV`). This was meant to ride #1110, which merged first, so it arrives on a fresh branch from `main`.

**How it works.** `.github/workflows/branch-sweep.yml` runs `tools/branch_sweep.py` daily at 06:17 UTC with a token allowed to push. It reads every `claude/` branch and keeps one while any of these holds:

- a pull request is open from it, or onto it;
- docket reads unfinished work on it (`claims.unfinished_work`, the test `flight` already settles a branch by), or a release cut;
- it holds the only copy of an item, or an edit to an item still open on `main` (`vcs.stranded`);
- a merged pull request left commits on it (`vcs.orphaned`, and `tools/left_behind_check.py`);
- its last commit is under 72 hours old.

Each of those is an existing detector, so the sweep adds no judgment of its own and never hides what the session-start digest would report for recovery. Any other branch goes in one atomic push that copies its tip to `refs/archive/BRANCH/TIP` and deletes the branch, leased on the tip it judged, so a branch pushed to since is left alone. An archive ref is outside `refs/heads` and `refs/tags`: no branch list shows it and no clone fetches it unasked, but it keeps the commits. The log prints the restore command beside each branch. If any reading fails (no token, no network, a shallow clone), it pushes nothing and the run goes red.

**One judgment call.** An edit to an item `main` has already closed does not keep a branch; its lines go into the archive with it. That covers four of today's stale branches: three hand-off drafts of `PL-N162` and one edit to `PL-PNJF`, both closed on `main`, which `PL-P99G`'s review found nothing in to carry over.

**Dry run against the real remote, 2026-09-26:** 7 of the 14 stale branches go on the first run, and the other 7, under 72 hours old, follow within three days. Every branch with an open pull request or live work was kept.

**Research**

- A workflow token takes write access through `permissions` ("adding or removing access as required", [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)).
- GitHub's receive-pack advertises `atomic` and `delete-refs`, measured with `GIT_TRACE_PACKET` on a dry-run push. Without atomic support, git fails the push whole ([git-push](https://git-scm.com/docs/git-push)).
- GitHub accepts refs outside `refs/heads` and `refs/tags` and does not list them in its web interface ([community discussion #30507](https://github.com/orgs/community/discussions/30507), not GitHub's own documentation). A refusal would fail the atomic push and delete nothing.
- Scheduled runs use the default branch, lag at the top of the hour, and stop after 60 days without activity in a public repository ([events that trigger workflows](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows)).
- A successor session continuing on its predecessor's branch was weighed and not built: Projects threads get harness-named branches, and an abandoned session has no successor.
