## The problem

`PL-037` put the branch-vs-`main` check in the session-start hook, which is the only place fifty lines of bash could run: once, at session start, on a condition that develops *during* a session. A session opened to discuss the next piece of work while another session finishes something is told its base is current — and by the time the discussion becomes implementation, the other session has merged. Nothing looks again, so it surfaces at push time as a merge conflict, which is the rework cycle the check exists to prevent.

## What landed

`branch_state` in `vcs.py` is the decision: position, disposition (`current` / `restart` / `pull` / `merge`), the ids that landed on the base since the fork, and why it declined where it did. `render` turns one of those into a sentence and a command. `bin/docket branch` asks it at any moment. The hook is two calls with no git of its own.

```
Branch: claude/pl-k7qx-live is 1 behind main and 1 ahead.
  Merge main before your first edit, not at push time:
  git merge main
  Landed on main since this branch forked: PL-9Y42.
```

**Deliberately not built: the `rebase origin/main` recovery the brief named.** Telling "carries only its own capture commits" from any other commits means guessing, and a rebase of a pushed branch needs a force-push, which this project's squash-merge path exists to avoid. The two commands the hook already printed are kept, and a test asserts no third appears. Say the word if you want it anyway.

**Four things built beyond the brief, each because the move exposed it:**

1. The hook fetched **after** running the digest, so the stranded-item line was computed from the previous session's refs while the comment above it said the fetch was there to feed it. Order fixed.
2. The command fetches; the function does not. The brief put the fetch outside because `docket check` must run from a bare checkout — true of the *decision*, which is why `branch_state` never fetches — but a command whose one question is "has the base moved" would answer "current" from a ref nobody refreshed. `--no-fetch` is for the caller that cannot, and the output says which happened.
3. "No comparison exists" is separated from "the comparison could not be made". A detached HEAD, no base, and the default branch with no remote copy are the first, and the hook's silence there is preserved through `--brief`; a clone sharing no readable history is the second and still says so out loud.
4. `tests/unit/test_docket_digest_hook.py` stubbed `bin/docket`, so its four cases would have gone on passing against a hook that no longer did anything. They now install a shim that execs the real command and run with `cwd` set to the fixture — so they cover the whole path a session start takes (hook → fetch → command → git) on real shallow and unrelated-history clones.

## What this does not do — and it is your call

**Nothing calls it mid-session.** The brief said the gap closes "as a side effect rather than as a second mechanism"; it does not. `bin/docket branch` makes the gap *closable*, not closed — a command nobody runs closes nothing. Two ways to finish it, and I did not build either:

- **A line in the digest naming the command.** The digest is resent on every turn, so it is always in front of the session. Costs one line; relies on the session acting on it.
- **A `PreToolUse` hook on the first Edit/Write.** Fires whether or not the session remembers — `CLAUDE.md`'s own routing ranks this disposition first — but it is a second mechanism, adds a fetch to the first edit, and needs a once-per-session guard.
