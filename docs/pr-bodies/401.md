Closes `PL-S5LB` — the closure walk's blindness to renames.

## The defect

`_number_closing` recovered a closed item's pull request by walking `git log -- <path>` with no rename detection. `docket` names an item's file from a slug of its title, so editing a title renames it, and `bin/docket release` renames every item whose title has drifted — making a rename an ordinary event on the one commit that stamps the most items at once.

The walk stopped at the rename, whose parent does not hold the new path at all, and that is exactly the shape the closure test looks for: done here, not done in the parent. So the renaming pull request was recorded as the one that did the work — or, where its subject carried no number, nothing was recorded at all, which is the quiet half observed while cutting v0.3.9.

## Rename detection alone does not fix it

Worth stating, because it is what the brief prescribed. `--follow` reaches past the rename, but each commit it returns still has to be *read* at the name the file carried there. Asking `git show <rev>:<the name it has today>` of an older commit fails, `_run_git` answers a failed `show` with empty output, and the closure behind the rename goes on reading as "not done".

Measured against this repository: `--follow` on its own still answered `PL-3D2M` with `319` — a pull request for `PL-CC23`, which renamed the file in passing — against a true `313`.

So the walk now reads `--name-status -z`, whose rename entry carries both names, and compares each commit at its own name and its parent at the parent's.

## Verification

- **Real history.** `PL-3D2M` moves from `319` to `313`. Every other closed item in the store is unchanged.
- **Both symptoms are covered** by tests — recovering the wrong number, and declining where the renaming commit named none.
- **`_work_already_on_base` is unaffected.** `_landing_split` compares blob hashes, which are content-addressed and therefore rename-invariant.
- `make check` green: 1942 tests, 100% core coverage, 0 docket errors, 0 documentation errors.
