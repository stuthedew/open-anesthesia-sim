`PL-5B88` makes `docket verify`'s "no suppression added" check able to fail
on the two decorators that actually disable a pytest test. Until now it
reported `none` with `@pytest.mark.skip` or `@pytest.mark.skipif` in the diff.

**How it works.** `SUPPRESSIONS` is a list of tokens matched against each
added line. Each token is anchored on the left and open on the right. `@skip`
needed its `@` directly against the name, `pytest.skip` needed its two halves
adjacent, and `.mark.` breaks both. This change adds two entries:

- `mark.skip`. It is written without `pytest.` so that `@mark.skip` after
  `from pytest import mark` is read too, which is the same reason the sibling
  assertion check matches a bare `raises`. The open right-hand side extends it
  to `skipif`.
- `unittest.skip`, which the brief asked to be considered. It reads the
  standard library's `skip`, `skipIf` and `skipUnless`.

**Counted before landing, as a widening owes.** I replayed every added line
from `main`'s 1,115 non-merge commits (of 1,232) through the shipped module.
The list as it stood matched no added line at all. The widened list matches
exactly one: the `@pytest.mark.skipif(shutil.which("bash") is None, ...)`
guard in `tests/unit/test_stop_hook_patch.py`, added by `PL-WW08` in #300.

That line is a real directive: an environment guard, not a test silenced to
reach green. A branch that adds one now gets `REJECT` and goes to a reviewer.
Across the whole history that is one refusal in 1,115 commits, on a line a
reviewer should see. No prose matched in any suffix the check reads,
including `.toml`, `.cfg` and `.ini`. The count is recorded in the comment
beside `SUPPRESSIONS`.

**Pinned.** `test_a_pytest_mark_skip_is_a_suppression` is parametrized over
five forms: `skip`, `skipif`, the imported `@mark.skip`, a module-level
`pytestmark`, and `@unittest.skip`. Each case asserts that the decorator line
is exactly what the check reports. On the first commit, before the fix, all
five failed with `detail='none'`.

**What `none` means is now stated.** The docket README lists what each marker
reads, and names the forms none of them reads: `pytest.importorskip`,
`unittest.expectedFailure`, `self.skipTest`, a raised `unittest.SkipTest`, and
a `collect_ignore` in a `conftest.py`. None of those appears in that history
either. They are filed as `PL-DNZ0` rather than added here, because each one
needs its own test pin.

**Caught on the way.** The close-out audit refused this branch once, on its
own new test docstring. A backtick span wrapped across two lines, so on the
second line the strip paired the wrong backticks and left `mark.skip` exposed
as code. That is the documented behaviour, erring toward reporting, and I
rewrapped the docstring.
