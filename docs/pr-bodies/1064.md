**What.** `.claude/hooks/floor-interpreter-guard.sh` refused two things it exists to allow, and missed three it exists to refuse:

- A bare `python3` aimed at `subprojects/docket/src/` or `subprojects/docket/tests/` was refused as if it were the 3.14 product tree. Those are the 3.11 floor code `bin/docket` runs under the bare interpreter, and `subprojects/docket/pyproject.toml` is the file declaring that floor (`PL-GVFC`).
- A path in the command *after* a `python3` call was read as its argument. Plain `shlex.split` returned `'print(1)';` as the one word `print(1);`, so `python3 -c 'print(1)'; sed -n 1p src/...` was refused for the `sed` (`PL-GVFC`).
- The same tokeniser hid the interpreter in `true;python3 -m compileall src/`, `cd /x&&python3 src/a.py` and `(python3 src/a.py)`, so those passed (`PL-BBV7`).

**How.**

- `GUARDED` gains a second lookbehind, `(?<!subprojects/docket/)`. It names that one subproject rather than any `subprojects/*/`: a new 3.11 subproject would then be refused, visibly, where a general rule would silently admit a 3.14 one. The product tree stays refused bare, after `./`, absolute, and named beside docket's.
- The tokeniser is the one `gate-status-guard.sh` already uses: `shlex.shlex(punctuation_chars=True)` with `whitespace_split`, a newline read as `;`, and `(`, `{` and `!` opening the command they precede. One line more: a backslash-newline pair is joined first. Reading every newline as `;` would otherwise have turned `python3 -m compileall \` followed by `src/` on the next line into a missed refusal, where plain `shlex` had refused it by accident. A trailing `# comment` now ends the parse, so a path in it is nobody's argument.
- One splitter for the three hooks to import is `PL-PVW2`'s to build, and the Projects trial's Stream A holds that head, so it is not built here.
