You asked that text you explicitly request be added **without other, already-streamlined text suffering for it**. There is still no count limit — and this is why one is not needed: the harm a limit would cause was reachable without any limit in place, and the check could not see it.

## The hole

`check_resident_instructions` compared one number against one number: the resident line total in the working tree against the total at the default branch tip. Growth and shrinkage therefore cancel. A change that adds nine lines to `CLAUDE.md` and cuts nine from `.claude/rules/instruction-writing.md` reported `growth == 0`, raised **no advisory at all**, and read as a free diff.

That is exactly the outcome the check's own docstring says must never happen:

> *"a limit would be met by deleting a rule to reach a number, which is the one outcome the routing pass must not produce."*

The docstring used that to argue against a threshold — correctly — while the metric underneath stayed blind to the same outcome arriving with no threshold in sight. A session that read *"resident instructions grew 9 lines; every session pays this before it has read anything"* and went looking for nine lines to give back would have produced a clean report, with the deleted rule gone and nobody asked.

The rules most exposed are the ones written most tightly, because a session hunting for lines takes them where the prose looks compressible — and the safety-critical clinical-output standard is resident precisely because a session that opens no matching file must still see it.

## The change

Two changes, both to what the check *says* rather than to what it permits. Nothing is thresholded and nothing fails.

1. **A second advisory when a change both grows and shrinks the resident set**, whatever the two sum to. It is decidable from the per-file deltas already computed and needs no judgment. It does **not** catch a routing pass: moving a rule out to a path-scoped file shrinks alone, with no matching growth, and stays silent exactly as today.

2. **The growth advisory stops reading as a budget.** It named the cost and then listed only routing as the remedy, which left a session holding a number it could not honestly reduce plus an implied instruction to reduce it. It now states two answers and no third — route it, or keep it and say why — records that *text the project owner asked for is the second answer, already given*, and says plainly never to trim other resident text to offset the number.
