## Why `main` is the only place this could show

`.github/workflows/quality.yml` runs the replay scoped with `--verify-base` on
a pull request, and unscoped only on push to `main`. #593 changed neither
`PL-S5YM` nor any file it declares, so **no pull request could have replayed
it.** The breakage was invisible until it was already on the default branch —
the case the session-start digest's red-`main` line exists to surface, because
no pull request will show it and nobody owns it.

It also defeats the guarantee in the direction that matters: `docket verify`
would **ACCEPT** a branch that did none of `PL-S5YM`'s work, and the store would
assert an item finished with its subject untouched. That is
`.claude/rules/apparatus-standard.md`'s floor exactly — what the apparatus tells
a session must be true.

## The fix

`PL-S5YM`'s `verify:` now keys on both halves of its own "Done when" rather than
on a test name:

```
grep -q 'covered_dirs' tests/unit/test_doc_check.py &&
! grep -q 'no tree draws one today' docs/ARCHITECTURE.md &&
uv run pytest tests/unit/test_doc_check.py
```

The test file must name `covered_dirs`, which only that item's work puts there,
and `docs/ARCHITECTURE.md` must no longer carry the clause the item exists to
replace. **Run against the tree as found, it fails** — as an open item's must.

`PL-S5YM` carries the account too, so the next session to open it is not left to
re-derive why its command changed.
