`_superseded` takes the whole outstanding set and spells it as one pathspec, and two of its three callers always handed it one. The third called it from inside `branches_in_flight`'s dict comprehension with a one-element tuple, so answering one question about one ref cost a `git diff` for every item file that ref had edited — a cost the session-start hook pays on every machine before the first turn.

## What changed

The candidate marks are collected in one pass over `walk.edited`, grouped by ref, and `_superseded` is asked once per ref. The two cheap filters still run first and the walk's order is kept, so the report is assembled exactly as before.

`_pathspec_chunks` bounds the pathspec at 64 KiB. Not because the command line would otherwise be too long — at ~60 bytes a path against the 2,097,152 `getconf ARG_MAX` reports on this container, it would not — but because of what happens if it ever were. `subprocess` raises on an over-long argv, `_run_git` turns that into the empty string, and a `--numstat` naming no paths is read as "the tips agree about every one of them", so every in-flight mark the ref carries would be dropped silently. Each chunk's absences are read against that chunk alone, since "git did not name this path" means "the tips agree" only about paths that call actually asked for.

The alternative the brief named — dropping the pathspec and filtering git's whole-tree output in Python — was refused for cost rather than contract: it makes every call parse the branch's entire diff to answer a question about its item files.

## Measured

`bin/docket digest --profile`, both runs on one checkout against a ref set that did not move between them — 25 refs, 6 merged, 19 unmerged, carrying 30 commits and 111 item-file edits. That control is the defect `PL-XD3C` records, where a 5x ratio was attributed to three different scaling laws because the two sides were counted hours apart.
