Before: each of the three Bash guard hooks split a command its own way, and each way differed from bash's. A `)` glued to the `;` or `|` after it hid the next command from the gate-status and floor-interpreter guards, so `(true); make check 2>&1 | tail -45` ran unrefused (PL-63TT, a silent miss). All three guards read nothing after the first `<<`, so a guarded command on any line after a heredoc was never seen, including after the commit message this repository writes through one (PL-39LD). And the gate guard read a backslash-newline as a separator, so it refused `set -o pipefail; uv run pytest -q \` continued onto `tests/unit/x.py 2>&1 | tail -5`, blaming a `;` the command does not contain (PL-R5RF).

After: `.claude/hooks/shell_split.py` is the one answer to where a shell command ends, and all three guards import it. The glued case is refused, a guarded command after a heredoc's terminator is read, and a continued line is one command. A heredoc's body is still removed, so prose about a hazard written through a heredoc is still allowed.

How: a standard-library lexer with bash's rules. Operators are matched longest first over bash's table; single, double and ANSI-C quoting keep a word whole; a backslash-newline is joined; a `#` comment runs to its line's end; a newline acts as `;` except after an operator; and each heredoc body is consumed at the newline that ends its introducer's line, quoted and `<<-` delimiters included, an unterminated one running to the end as bash's does. A `$(` inside double quotes is read recursively, so `git commit -m "$(cat <<'EOF' ...)"` removes the message and keeps the commit. It answers `words`, `segments` and `command_text`; a command bash itself would refuse gets `None`, and the hooks fail open on it as before.
