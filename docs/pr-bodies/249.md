## `PL-J49T` — the rule

`verify_required_at_close_from` in `docket.toml`, read by `config.py` and enforced by `_verify_required_at_close` in `checks.py`: an item with `status: done` whose `closed:` falls on or after the date must name a `verify:` command or a `not-delegable:` reason. `dropped` is excluded — an item that will not be done carries a reason, not a command for work nobody did.

**Keyed on `closed:` rather than `added:`, which is the entire design.** That is what lets it reach the items `verify_required_from` grandfathers. They are exempt at `ready` and stay exempt however long they sit there, so until now the only thing asking for their command was a grooming advisory — a signal that works if somebody reads it. Closing an item is the first moment its command can be written *having been run*, which is the objection that earned the exemption; that is where the exemption lapses.

**An error rather than a louder advisory** because the two halves separate cleanly: whether the field is present is decidable, and only *what it should say* needs a person. `CLAUDE.md` asks for exactly that split — find the decidable part and put it in code, do not script the judgment.

**Set to the day it landed, so it touches nothing already closed.** Measured before choosing the date: 182 items are `done` and 54 carry no command, several closed the day before. Backfilling those would mean writing commands with nothing left to run them against — the failure `PL-5YK8` refused at the other end of an item's life.

### What prompted it

The project owner asked whether the contrast checker's known-shortfall block is the same "advisory nobody reads" problem `PL-5YK8` fixed, and then whether an advisory being *behavioural* is itself the defect. It is, for the decidable half. Recorded in the item rather than left out: this session filtered `make check` through `grep` for summary lines and read "1 advisory" across several runs without reading the advisory text, while the item count moved 116 → 118. Nothing was lost, because the content had not changed — but the method would not have noticed if it had.
