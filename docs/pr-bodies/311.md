Replaces min/max envelope decimation with **M4** as published (Jugel et al. 2014, held in `docs/references/`) and keeps its four aggregates in a dyadic ladder anchored to absolute sample index, so a completed bucket is final and a frame reads what it draws rather than what the window spans.

## The cost was three passes over the window, not one

The item was written against the rescan, which is 81% of the cost. The other 19% would have kept the frame proportional to the width shown whatever the cache did, so all three are gone: the window copied its samples out, each trace built a list of one field per sample, and the wash-in plot reclassified every visible sample against its domain.

`RunHistory` therefore replaces the controller's `list[SimulationHistorySample]`, storing the run **by quantity** with one `M4AggregateCache` each. `HistoryWindow` becomes a range over it rather than a copy of its samples — safe because the cache is append-only and every read is bounded by an explicit stop, which closes the stale-state hazard the copy guarded against structurally instead.

Recording costs 4.6 µs per sample across all seven caches — 46 µs of CPU per second of simulated time at the 0.1 s step. Memory **fell**: 127 B per sample including the ladders, against 264 B for the list of rows it replaced.

## What the chart may claim

The module docstring and `docs/MODEL.md` both state where this departs from the paper: Theorem 1's exactness holds only when the group count is an integer multiple of the pixel-column count, and a grid anchored to the run cannot also be that. It buys stability at that cost and lands in the paper's general case. Of §4.3's three error classes, E1 and E2 need gaps in the sampling and this simulation has none, so only E3 can arise.

Carrying four sample *indices* rather than two values is a correctness requirement: an extreme replayed at a bucket boundary would be a synthesized point, and `chart_downsampling.py` guarantees every drawn point is a recorded sample.

## Three items this falsified

- **PL-CG7J** was promoted to a prerequisite on the reasoning that four tuples per column would halve the affordable columns. Measured, a steady frame still sends 24 patch operations and a trace draws 182 points against the envelope's 190 — M4's four tuples collapse to two on a monotone stretch. Un-promoted, sequenced against nothing.
- **PL-SSBP**'s scales past an hour were blocked on this cache. They are not any more.
- **PL-011**'s memory table was sized against the list of rows; halve it. Its eviction rule is untouched and still open.

## Tests

`tests/unit/test_chart_downsampling.py` is rewritten against the definition rather than against another version of itself: every range of a run with gaps is compared to M4's Definition 2 read straight off the values.
