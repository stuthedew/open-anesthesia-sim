## What changed

A run is now held as the settings in force at each moment — the *score* — plus
one keyframe per setting change, and every state it passed through is derived
from those rather than recorded. `src/anesthesia_sim/core/run_score.py` is the
new module; `SimulationController` builds a score beside its `RunHistory`,
moves its reach with each completed step, records a segment wherever the core
accepts a setting change, and answers `evaluate_window(start_s, stop_s,
columns)` from it.

Two evaluation paths, deliberately distinct:

- `state_at` is canonical — one matrix exponential per inter-event interval,
  composed in recording order from t = 0, so two evaluations of one score at
  one instant are bit-identical. Keyframes are computed this way.
- `evaluate` is the display path — inside a segment it reuses one propagator
  across uniformly spaced columns, which is what makes a frame cheap and which
  composes the same operations in a different order.

`PL-P1Z3` is what states that separation as a guarantee in `docs/MODEL.md` and
gates it; this branch builds the structure it will gate and says so in the
module docstring rather than claiming the guarantee early.

## Measurements, corrected against the item's prototype figures

Re-measured with `tracemalloc` and `perf_counter` on the shipped code rather
than carried over from the brief:

- **Memory.** The recorded history costs 130.8 B per sample, so 30 days at the
  0.1 s step is 25 920 000 samples and 3.16 GiB. The score of the same case —
  a busy ICU month at 50 changes a day, 1 501 stretches — is **1.6 MiB, not
  the ~140 KiB the brief estimated**: a stretch carries a whole
  `UptakeEquationSettings` and Python object overhead is about 1.1 kB of it.
  The ratio is still about 2 000x.
- **Frame cost stops following the run.** A 1 h window at 600 columns costs
  10.6 ms on a 2 h run and 13.0 ms on a 30-day one, against the 62.6 ms at 4 h
  and 207.7 ms at 12 h `PL-011` records for the rescan this replaces.
  `test_a_window_reads_only_the_segments_it_covers` pins that structurally, by
  counting propagators rather than by the clock.
- **Where cost does still move** is setting changes *in view*: a full 30-day
  span at 600 columns is 14.2 ms with two changes in view, 231 ms with sixty,
  about 1.1 s with six hundred. That is the regime where 600 point samples
  alias the run anyway, so what to draw there is `PL-2FM6`'s question.

The item's brief carries all three corrections.
