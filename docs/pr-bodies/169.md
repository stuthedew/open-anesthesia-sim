Closes `PL-99Y4` (a closure with no `pr:` turns `main` red one merge later). Both options, approved 2026-09-01.

## What was wrong

`main` went red on `97573ae` and `3b37a75` for a `pr` that was never missing.

The closure rule `PL-P5S0` set is right: the number does not exist when a closure is committed with its work, so an empty `pr` on the base is the normal shape of a merge, and `check` already softens that to an advisory where the merge commit names the number. What it never asked was **whether the checkout could see that commit.** CI checks out at `fetch-depth: 1`, so a closure stayed an advisory on its own merge commit and became a hard error one merge later — when nothing about the provenance had changed and only the horizon had moved.

The error's own wording is the tell: *"there is no way back from the closure to the work that made it."* The way back existed in git the whole time.

## The source fix

`ClosureReport` gains `shallow`, straight from `is_shallow`, and `_check_closures` errors only where it is `False`:

| history | no commit names a number | verdict |
| --- | --- | --- |
| complete | provenance genuinely lost | **error**, as before |
| truncated | the commit may be out of reach | **decline**, naming the ids |
| `is_shallow` won't say | same | **decline** |

A *derived* number stays an advisory at any depth — finding the commit is proof it was there to find. Truncation qualifies an absence, never a hit. That is the rule `PL-J295` already established for `tags` and `merged_pull_requests`, applied to the question sitting beside them.

## The other half, and why measuring first raised its value

Both checkouts move to `fetch-depth: 0`. I ran the full history before writing the line, and it buys more than the item predicted: `bin/docket check` and `tools/doc_check.py` **both lose their "not checked" section entirely.** Three checks CI was silently not running — release tags, recorded pull requests, and the missing-`pr` read — go from declined to passing. So it adds coverage rather than risk, and the history is 498 commits.

The two halves fit: the decline stops false failures everywhere, and the depth gives the check one environment where it can genuinely answer.
