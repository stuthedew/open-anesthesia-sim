Gate 1 entry. `docket.toml`'s `workflow_paths` named three apparatus test files individually; nine more were in the same position, two of them having arrived the previous day.

## Why the hand-list was not simply completed

The item offered three shapes: another entry per file, a prefix that catches the family, or a naming-convention matcher. The first is what had already drifted, and there is no prefix — the apparatus tests are interleaved with product tests in `tests/unit/` because that is where pytest is configured to look. A `test_*_check.py` convention would catch seven of the twelve and miss the four `.claude/hooks/` tests and `test_tools_portability.py`, which is worse than nothing: it would look complete.

So the membership rule moved into code. `tools/workflow_paths_check.py` decides each file's side from the file itself and `make check` fails until `docket.toml` agrees.

## The rule, and why it is a hard failure rather than an advisory

A test file under `tests/` is apparatus when it does not import `anesthesia_sim`, and the simulator's when it does. Measured across the tree before it was written:

| | count |
| --- | --- |
| `tests/unit/` importing `anesthesia_sim` | 26, all product tests |
| `tests/unit/` not importing it | 12, precisely the twelve apparatus tests |
| `tests/integration/`, `tests/reference/` | all import it |

No file in the tree needs a judgment, which is what earns a hard failure. The check asks only what a file imports, never whether it should exist — everything else about the list (directory entries, `ROADMAP.md`, `docs/ARCHITECTURE.md`) stays a judgment argued in `docket.toml`'s own comments.

The rule also keeps working on files nobody has written yet: the next `tools/` check's test will import `tools/`, not the simulator, without anyone deciding to make it so. It caught its own test file the first time it ran.

`ast` rather than a grep for the package name, because several apparatus tests write `src/anesthesia_sim/...` as fixture data — they check tools that read the tree — and as text that looks like a dependency.
