Closes `PL-J2TD` (open a live run at a canonical keyframe state, which is what a fork resumes into), the last v0.5.0 Required-scope entry that stands between a fork and something a learner can manage. `PL-TFX5` (fork a run at any control-input event) is blocked on it; `PL-CTD7` (detect a bookmark crossing inside the advance loop) presupposes it.

## What it does

`SimulationController.resumed_at(elapsed_s)` returns a second live run standing at this run's canonical state at a keyframe. It advances by the path every run takes — `advance()` is not overridden and no second way to move a run forward is introduced.

Underneath it, `AgentUptakeSystem.resume_at(state, initial_agent_l)` stands a live system at a canonical state vector, and `governing_equations.require_canonical_state` is the entry guard the run definition and the live system now share, so the two cannot come to disagree about what a state is.

## The design question, and how it was settled

Which clock a branch keeps. The run's own clock **continues the case's**; the *definition* is what is re-based, by subtracting the fork instant in `advance` and `drawn_window`, which is what `docs/MODEL.md` § "The canonical evaluation rule" gates. The alternative — a branch whose step count restarts at zero — is wrong rather than merely untidy, on three counts, each measured rather than argued:

- **The 24 h supported run length is enforced on the step count alone.** A branch restarting it is handed a fresh envelope: a fork at 23 h could be advanced to 47 h of case time with every guard passing, in exactly the regime `core/supported_ranges.py` argues the omitted metabolism dominates the trace. Continuing the parent's count closes that in the guard's own integer arithmetic, with no new code and no second statement of the envelope.
- **The clock, every control-change stamp and the chart's axis all read `snapshot().elapsed_s`**, which `format_elapsed` says they "state one quantity one way". A branch counting from zero puts the patient at the wrong point on the uptake curve on all three at once.
- **Elapsed time stays one multiplication**, `(k + n)` steps times the step, rather than the fork instant plus the branch's own — which § "Simulated time is a count of steps, not a running total" is the rule against.

This is compatible with the described mechanism rather than a substitution for it: `docs/MODEL.md`'s re-basing bullet constrains the *definition's* clock, and the definition is re-based exactly as written. The safety-critical standard puts the envelope question outside what a session weighs.

## Refused rather than approximated

An instant the run holds no keyframe for, naming the ones it does; a non-finite instant; a fork instant that is not a whole number of the run's steps; a branch of a branch (`PL-TFX5`'s flat shape); a replay that does not reproduce its own segment; and, in `core`, a display value, a wrong-length state, a non-finite entry, a unit state that is not one, a negative cumulative total or a negative anchor. A refused resume restores the system, by the route `advance()` already uses.

`reset()` on a branch returns it to its fork rather than to zero, because that is where a branch began — clearing to an empty system would stand the patient at no agent at a case time the model says they are loaded.
