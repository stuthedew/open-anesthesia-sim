Closes `PL-97VB` (nothing stops a future identity-carrying control being disabled), the class `PL-61WW` fixed one instance of.

## The rule, and who decided it

The project owner, 2026-09-08, from the two the item posed: **never disabled**, rather than *declared colour if disabled*. It needs no new constant, and it is the position `PL-61WW` already put the tree in.

*Rendered* is the load-bearing word. `_agent_dropdown` is still assigned `disabled = snapshot.is_running`, and is also assigned `visible = not snapshot.is_running`, so it draws nothing while disabled — that `disabled` line is there because a control off screen must not be operable either. A check reading `disabled` alone would fail the merged tree and teach the next session to delete a defensive line to appease it, which is the tail wagging the dog. So what is enforced is the pairing: an identity-carrying control may be disabled only where the same expression, negated, also hides it.

## The two rules, both syntactic

1. **The identity set is whatever `_apply_agent_color_scheme` writes.** That method is already this project's single writer of agent colour and says so in its own docstring, so no second list has to be kept in step by hand.
2. **A control given an agent colour where it is constructed must be in that set.** This is what makes rule 1's coverage claim true rather than asserted, and it is a bug in its own right — a control keeping the colour it was built with shows the previous agent's identity over the current agent's numbers.

A missing writer, or one that writes nothing, is an error rather than an empty pass: a coverage set that can silently go empty is worse than no check.

The pairing comparison is **structural**, deliberately. `visible = snapshot.is_paused` beside `disabled = snapshot.is_running` may well be correct, and the check still rejects it — proving two conditions equivalent is the judgment half, and a tool that guessed would report a pass it cannot support. One canonical shape, and a failure naming that shape. What it must never decide (legibility, whether a pairing is the right one, what colour anything should be) is written into the module docstring, the same line `tools/contrast_check.py` draws.
