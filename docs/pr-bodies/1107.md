Before: `timeout 600 make check | tail -5`, `timeout 60 python3 -m compileall -q src/anesthesia_sim/` and `timeout 60 git fetch --prune` each passed the Bash guard that refuses the same command without `timeout`. A red `make check` run under `timeout` and piped to `tail` could reach a session as exit 0.

After: a gate, a floor parse or a prune run under `timeout`, `env`, `nice`, `nohup`, `xargs`, `command` or `exec`, nested or with the wrapper named by path, is refused exactly as the bare command is. `command -v git`, and a wrapper around a command no guard names, are still allowed.

The guards compared a command's first word with the program they guard, so a program that runs another was read as the command itself.

How: `.claude/hooks/shell_split.py` gains `program_words`, which reads past each wrapper to the program it runs. Each wrapper is read by its own option grammar (`WRAPPERS`), taken from `timeout --help`, `env --help`, `nice --help` and `nohup --help` in coreutils 9.4, `xargs --help` in findutils 4.9.0, and `help command` and `help exec` in bash 5.2.21: which options take a value, which bundle, which long options abbreviate, and which stop the read because the wrapper runs nothing (`command -v`, `--help`) or runs a string this does not split (`env -S`). All three guards now read a command's program through it. The gate guard still reads past `uv run`, with a wrapper on either side of it; the floor guard still admits an interpreter named by path, its deliberate spelling; the prune guard now reads a path to `git` as `git`. The gate guard's `sets_pipefail` deliberately keeps reading from `command_words`, since `timeout 5 set -o pipefail` runs `set` as a program, which is not found.

Tests: `test_a_wrapper_runs_the_command_after_it` in each of the three hook suites pins every spelling the item reproduced, each wrapper by its own grammar, nesting, a wrapper named by path, and the spellings that must stay allowed. Locally, `make check` passes (5,020 tests) and `bin/docket verify --self PL-TRMN` answers ACCEPT.

Filed on this branch while triaging, not worked here, and next on the project's list after this merges:

- PL-9RSP: `command set -o pipefail` is refused although the pipefail setting holds.
