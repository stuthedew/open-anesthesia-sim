`PL-CPSY` (a squash-merged branch whose ref survives reports its items in flight forever), an entry of the v0.2.8 gate.

## The defect

`branches_in_flight` excluded a ref by containment alone: a branch whose tip `--merged=origin/main` names is finished. A squash merge writes one *new* commit onto the default branch carrying the branch's content and none of its commits, so a squash-merged branch is never contained — its ref stays a candidate for as long as the checkout holds it, and every id leading one of its commit subjects reports in flight permanently. `in_flight_ids` feeds `docket next`, which excludes what is in flight, so a stale ref makes `next` withhold startable work with no line of output saying so.

`stranded` already documented this trap from the other side; this is the same rule applied to the in-flight read.

## The fix

Each candidate ref is now also tested by content. Every blob the ref adds to the tree it forked from is looked for in the default branch's **history** (`git log --find-object`), and a ref whose every blob has been there carries nothing unlanded — however its commits got there, squashed, rebased or cherry-picked. The merge-base that decides whether a ref can be answered at all is the fork point the test compares against, so the two reads cannot disagree about where the branch left from.

The history rather than the tip, because a tip comparison un-lands the branch the moment anyone edits a file it touched — which here is routine, since the triage pass that follows a capture rewrites the very file the capturing branch added. This checkout's own surviving squash-merged ref is exactly that case: its blob is in `origin/main`'s history while its content differs from the tip, so a tip comparison would still be calling it unmerged.

A ref that adds no blob this checkout can read — no commits yet, only deletions, or a fork point beyond a truncated clone's horizon — stays in the report. Silence is not evidence of landing, and the two errors are not equal: naming a merged branch is noise, dropping a live one hands its item to a second session.

## Scope

`PL-MGNC` (a shallow clone's `^base` walk reports merged items as in flight) and `PL-S1P1` (the unread refs are dropped from the ids) are the other two holes in this function and are left open; this change removes the mechanism that produced the incident `PL-MGNC` records, but not `PL-MGNC` itself.
