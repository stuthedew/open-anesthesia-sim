Closes **PL-026** (make the simulation step transactional so a halt leaves no partial state), and with it **PL-KQKM** (MODEL.md says a failed step is abandoned; the code leaves partial state) and **PL-YLZQ** (PL-026's brief sends a reader to WORKING_NOTES for its own reasoning).

## The defect

`RespiratorySystem._advance_step()` applies five sub-exchanges in sequence, and a compartment guard can reject the fifth after the first four have already written their state. PL-018 halted the run and warned that "the values shown may not reflect a completed step", but the metrics and chart traces were still drawn at whatever the abandoned step left them — numbers that are an artifact of the order the operators ran in (step 5 having run against step 2's output), not a solution of the model at any time, and not distinguishable in the interface from numbers the model produced.

## The change

`advance()` captures every dynamic value before the step and restores it on any failure. A halted run now holds the last completed step: a real solution, at a real simulation time, which the interface may display and a reader may reason about. The diagnosis moves into the raised `SimulationNumericalError` message, which names the invariant that failed and the step size it failed at.

- **Capture lives on each compartment**, not in `RespiratorySystem` — `capture_state()` / `restore_state()` over a frozen state record per class. A dynamic field added later without a matching capture is then a local, reviewable omission rather than a partial restore that looks complete.
- **Restores assign fields directly**, bypassing setters. The rollback runs while a failure is already being handled, and one that could itself raise would leave exactly the partial state it exists to prevent.
- **The rollback is wider than the guard it was written for.** An accounting failure or a `TypeError` from a later refactor leaves the same partly applied step, so both roll back; only a guard reached during the step is restated as `SimulationNumericalError`, and anything else re-raises unchanged, so a programming error is not dressed up as a modelling failure and `AgentSimulationValidationError` keeps its type.
- **Rolling back does not make the run resumable.** The model reached a state it could not step from, so the same step would fail again. What the rollback settles is what the caller may *show* while stopped — the banner now says the values are the last completed step instead of warning about them.

One departure from the item's inventory: `AgentSimulationValidator.initial_agent_l` is captured too, nine values rather than eight. It anchors the current accounting period and only `reset()` writes it, which is what makes it run state rather than a setting under the same rule every other compartment follows.

- `tests/unit/test_state_capture.py` — the coverage risk, guarded deterministically rather than by review.
