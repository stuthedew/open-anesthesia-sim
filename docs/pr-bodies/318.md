## The change

One bullet added to rule 14 of `.claude/rules/instruction-writing.md`. Before recommending repository work that carries no item id, read `post_turn_summary.needs_action` on the `RUNNING` and `IDLE` rows of `list_sessions`; where another session already asks for it, name that session instead of repeating the request.

Rule 14 is where it fires. It requires a closing block of every reply, so the check runs at the moment the recommendation is written, in every session, without the `docket` skill having to be loaded — which matters, because one of the two sessions observed colliding on the v0.3.8 tag was working a product item and had no reason to load it.

## Why resident rather than routed

Weighed against `CLAUDE.md`'s four dispositions:

- **Not a check or script.** The decidable half — is there another live session holding an open recommendation — is worth nothing without the judgment half, which is whether that session's prose describes the same work as yours. Scripting that would be the guessed-judgment failure `CLAUDE.md` warns about.
- **Not a skill.** The colliding sessions had no reason to load one.
- **Not path-scoped.** No file read precedes writing a closing block.
- **Resident**, on `CLAUDE.md`'s own test: a session writing its closing block would not think to look anything up.

The resident-growth advisory fires at 18 lines and the item records the answer it asks for. Cost: 18 resident lines, against a measured collision cost of one session's release work.

## What it deliberately does not do

It warns and never certifies, on the same bound as every other guard here: the match is a judgment on another model's prose, a session still mid-turn has not written its line yet, and two sessions closing in the same minute still collide. Finding nothing means nothing; finding something is decisive. Its one structural advantage over the title read is that the field is written by the harness, so its reliability is bounded by the reading session's behavior rather than by the other session's.
