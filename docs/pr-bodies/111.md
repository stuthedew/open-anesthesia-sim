## PL-N7R9 — the pull request arrives with the work

`CLAUDE.md` said "open a pull request only when asked". By the time it is
asked, the owner has already approved a design and said go, so the question
costs a full turn — the whole context resent — and carries no decision.
`PL-Z8SV` kept that ask because a pull request is the act asking for someone's
attention. True, and wrong about when: it put the asking after the point where
the attention had already been given.

Two limits are stated because without them the rule reads wider than it is:
approved work rather than any commits, so a capture-only session's branch is
not a pull request; and the web harness's own instruction not to open one
unasked is resolved outright, since the bullet is that ask given as standing
policy rather than per pull request. (This pull request is the first thing
opened under it.)

## PL-J295 — a truncated clone declines instead of answering wrongly

`make check` failed on unmodified `main` in every web-session container:

```
ROADMAP.md:37: v0.0.1 is marked completed but git holds no tag for it
```

...and seven more. The tags were not missing. The container clones shallow, the
older tags point outside the fetched depth, and `git tag --list` returned 3 of
11. `git fetch --tags` then passes.

This is `PL-XCYB`'s defect one reader over. `check_tags` guarded the case where
git returns *no* tags; a shallow clone returns a **partial** set, which walks
straight through the guard. `vcs.is_shallow` now names the state, extracted
from `merged_pull_requests`, which was already asking git the same question
inline.

The guard is deliberately narrower than "decline in a shallow clone" — the
session container and `actions/checkout` both clone shallow, so that would
retire the check everywhere it actually runs, including checkouts that have
since fetched their tags and can answer exactly. Findings are computed first
and withheld only when there is one *and* truncation could account for it. A
tag being **present** is never in doubt, so those conclusions are untouched.

The regression test builds a real `--depth=1` clone and asserts the tag set is
genuinely truncated, so it cannot quietly stop testing the case; a second test
holds the decline to its scope.
