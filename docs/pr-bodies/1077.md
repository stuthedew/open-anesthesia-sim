## What was broken

`claims.in_queue` counted the items, the roadmap and the working notes as the queue, and left out `docs/pr-bodies/`. Since PL-979D (#1068), `pr-title`'s required job fails unless the head holds the pull request's body record there. So on a branch that changes only the queue and claims nothing (a capture, a triage pass, a design round), the two required checks could not both pass. `pr-title` failed without the record, and `checks` failed with it, at `tools/branch_id_check.py`'s "this branch claims nothing". This is what holds #1066. `flight`'s `unclaimed:` row asks the same `claims_nothing`, so it also counted every such branch as a forgetful session.

## What changes

- `claims.RECORDS = "docs/pr-bodies/"` sits beside `in_queue`, and `claims.queue_records(config)` is the one list that `in_queue` counts and `branch_id_check._queue_named` prints. This bug was missing from both, and the two now cannot drift apart again.
- `in_queue` counts a path under a directory entry (one ending in `/`) or equal to a file entry.
- `.claude/hooks/docket-branch-guard.sh`'s comment said a capture writes "only item files", which has been stale since PL-3CTW. It now says the queue.

## Decided on the way: CI no longer asks a `--recover` pass for a claim

The whole directory counts, as it already does for `arm` and `verify`. Telling a branch's own record from a recovery takes more than the path: it needs each file's header, or the base's squash subjects. That would buy a refusal for a pass with almost nothing left to do. `pr_body_check.recovered()` counts every record, so no pull request that recorded its body is ever reported lost, and the session-start digest reported two lost bodies left today. `CLAUDE.md`'s housekeeping rule still files and claims such a pass. Only CI's enforcement of that goes, and `in_queue`'s docstring says so.

## Open question: does `arming.py` import `claims.RECORDS`, or keep its own copy pinned by a test?

The brief proposed the import. That would move part of what arms on green out of `arming.py`, the one file the gate holds for a read. `claims.py` is under `subprojects/docket/`, which arms on green. So a one-line edit widening `claims.RECORDS` (to `docs/`, say) would itself merge unreviewed, and from then on `arm` would pass pull requests touching `docs/MODEL.md`. Today that widening takes an edit to `arming.py`, which holds.

**Recommendation:** keep `arming.RECORDS` as the gate's own copy, and add a test pinning `claims.RECORDS == arming.RECORDS`. The cost is that the directory is spelled twice, so changing it takes two edits. `arming.py` and `verify.py` are untouched until you answer. The item's `verify:` names the pin test and fails until the answer lands.
