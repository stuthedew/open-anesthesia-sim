## What was broken

`claims.in_queue` counted the items, the roadmap and the working notes as the queue, and left out `docs/pr-bodies/`. Since PL-979D (#1068), `pr-title`'s required job fails unless the head holds the pull request's body record there. So on a branch that changes only the queue and claims nothing (a capture, a triage pass, a design round), the two required checks could not both pass. `pr-title` failed without the record, and `checks` failed with it, at `tools/branch_id_check.py`'s "this branch claims nothing". This is what holds #1066. `flight`'s `unclaimed:` row asks the same `claims_nothing`, so it also counted every such branch as a forgetful session.

## Decided on the way: CI no longer asks a `--recover` pass for a claim

The whole directory counts, as it already does for `arm` and `verify`. Telling a branch's own record from a recovery takes more than the path: it needs each file's header, or the base's squash subjects. That would buy a refusal for a pass with almost nothing left to do. `pr_body_check.recovered()` counts every record, so no pull request that recorded its body is ever reported lost, and the session-start digest reported two lost bodies left today. `CLAUDE.md`'s housekeeping rule still files and claims such a pass. Only CI's enforcement of that goes, and `in_queue`'s docstring says so.
