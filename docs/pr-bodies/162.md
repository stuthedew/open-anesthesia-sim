## What this fixes

`~/.claude/stop-hook-git-check.sh` picks its comparison point with

```sh
if git rev-parse "origin/$current_branch" >/dev/null 2>&1; then
  upstream="origin/$current_branch"
```

which tests whether the ref *resolves locally*, not whether the branch exists on the remote. `PL-1Q3S` (a merged PR leaves a stale tracking ref, so the stop hook demands a push that would recreate a dead branch) diagnosed that and is `done` — but it recorded only the merged-pull-request way to acquire such a ref, and the `CLAUDE.md` bullet it produced is keyed to that moment.

There is a second way, and it is the quiet one: the web harness seeds a remote-tracking ref for the session's own branch, pinned at `main`'s tip, before the session has pushed anything. Observed here on `claude/next-priorities-regxtv`:

```
$ git ls-remote --heads origin | sed 's#refs/heads/##'
Review_articles
add-claude-github-actions-1788276784576
claude/working-notes-redundancy-4bp5xm
main

$ git rev-parse origin/claude/next-priorities-regxtv
d5bfbff0dcf8c764550a5c57ded9eb44d7b552ab
```

The branch was on no remote, yet its ref resolved — pinned at the `main` tip the session started from. The session then did nothing but `git fetch origin` and fast-forward onto a merge, and the hook read that one commit (already on `origin/main`) as unpushed and demanded a push. `git log origin/main..HEAD` was empty.

The trigger is therefore *any* session that fetches `main` without committing — a "what next", a status question, a design round. Those are exactly the sessions with no work to push, so the demand is unanswerable rather than merely wrong: the session either spends turns disproving it or pushes a branch identical to `main` with no content and no pull request. This session spent four turns on it.

## The change

Widen the condition of the existing `CLAUDE.md` bullet; keep its remedy. The bullet now leads with the general fact (a remote-tracking ref that resolves locally is not evidence the branch exists), names both ways a stale one arises, and gives the two commands that decide it — `git ls-remote --heads origin` for whether the branch exists, `git log origin/main..HEAD` for whether there is anything to push.

Widened in place rather than joined by a second bullet, so the diagnosis is stated once. `CLAUDE.md` +4 lines, which `doc_check` raises against `PL-H7XN`'s resident-line test; the justification is recorded in the item. The routing test puts this in tier 4 rather than tier 1: a session needs it when the stop hook fires at the *end* of a session, and no `.claude/hooks/` check can fire then. The session-start digest already said "current with origin/main (0 ahead)" in the very session that then spent four turns disproving the hook — so an earlier deterministic signal is not what was missing. The bullet a session reaches for once the hook has spoken is, and its condition excluded this case.
