Before: `2>/dev/null make check | tail -5`, `2>/dev/null python3 -m compileall -q src/` and `2>/dev/null git fetch --prune` each passed all three Bash guards, and so did the same commands with the redirection among a wrapper's words (`timeout 5 >x make check | tail`, `env 2>/dev/null git fetch --prune`) or among the program's own (`bin/docket 2>/dev/null check | tail -5`). A red gate written that way could reach a session as exit 0.

After: each is refused by the guard it concerns, exactly as the command without the redirection is. A redirection's target is no longer read as an argument either, so the floor guard stops refusing `python3 x.py > src/out.txt`, which parses nothing under `src/`, and still refuses `python3 < src/a.py`, which parses the file it reads.

Bash lifts a redirection out of a simple command wherever it stands before it runs anything (POSIX.1-2017 XCU §2.9.1; bash 5.2.21 prints `a b` for `echo a 2>&1 b`). The shared reader returned `2>/dev/null` as the word `2`, then `>`, then `/dev/null`, so each guard took `2` for the command, a wrapper stopped reading at the `>`, and git's own options stopped at it too.

How: `.claude/hooks/shell_split.py` now marks a descriptor - a number or `{name}` written against a `<` or `>` operator, unquoted - as `Descriptor`, POSIX's IO_NUMBER and bash's `{varname}`. One function, `_redirection`, says how many words a redirection takes: its descriptor, its operator and the word after it; a `<(` or `>(` is a process substitution rather than a redirection. `command_words` drops redirections ahead of the command's name with the assignments, in any order, so it still drops only a prefix; `program_words` lifts every redirection out of the words it returns, before reading past wrappers, so all three guards see the words bash hands the program. `redirections()` gives the floor guard what goes onto an interpreter's standard input (`<`, `<>`, `<<<` on descriptor 0), which is how `python3 < src/a.py` stays refused. Each shape was checked against bash 5.2.21: `timeout 5>x echo ran` fails with `invalid time interval 'echo'`, while `timeout 5 >x` and `timeout '5'>x` run `echo`; `echo hi 2&>x` writes `hi 2`; `echo 2>(cat)` prints `2/dev/fd/63`; and `2>/dev/null set -o pipefail` holds for the pipe after it.

Tests: `test_a_redirection_is_not_a_word_of_the_command` in each of the three hook suites, 21 cases. 16 fail on `main`'s hooks; the other 5 are controls that pass on both, two of them pinning the standard-input refusal this change had to keep. Locally, `make check` passes (5,041 tests) and `bin/docket verify --self PL-K9QL` answers ACCEPT.
