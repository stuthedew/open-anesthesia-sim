**Problem.** Close-out step 8 gives the reviewer each paragraph of 30 words or more that the branch changed, and nothing else. It asks for a rewrite no longer than the text it replaces. Three things follow.

1. The reviewer cannot see that a new paragraph repeats, or belongs inside, an unchanged paragraph beside it.
2. The length cap is the old paragraph, so a padded paragraph sets its own ceiling. A new paragraph has no cap at all.
3. `.claude/rules/plain-writing.md` says rewriting sentences a branch did not need to touch is work for its own item. So a fix adds a paragraph to a section and never merges it into what is there. Only a separate prose item ever shortens a section.

**Measured 2026-11-03.** The passage of `docs/MODEL.md` § "Displayed precision" from "The MAC resolution is derived from this one" to "silently over-claiming" was 381 words on `main`. `PL-ZDZ0` corrected one false sentence in it, and three prose-review rounds and the owner's request to shorten it brought it to 366 words at `ecf15dff6`. A rewrite of the whole passage, ordered for the clinician with the derivation and tests in a developer note, came to 260 words. It kept every value, unit and test, and passed `tools/doc_check.py` and `tools/literal_home_check.py` unchanged.

**Recommended.** Change the review's unit from the changed paragraph to the passage it sits in: from the heading above to the next heading, with the changed paragraphs marked. Ask for the shortest version of that passage that keeps every fact, ordered for its first reader. Allow the branch to rewrite that passage, and only that passage, even where its sentences did not need to change. Report the passage's word count before and after in the pull request. A passage that grows says what the added words buy.

**Why it matters.** A fix branch can only add to a section, so each section grows until a separate rewrite item shortens it. The clinician reading `docs/MODEL.md` gets the point later in each round, and the seven open `prose-quality` rewrites are the cost so far.

**Cost.** Diffs on fix branches get larger, and a safety-tagged fix that waits on the owner's review gives them more to read. Limiting the licence to the passage the fix is in keeps that to a few paragraphs.

**Build plan, 2026-11-04.** It was written before a reset for length, when nothing below was built yet and `PL-JP8X` had merged first, as #2014.

1. **What the copy editor may rewrite.** It reads the whole section around a change, but rewrites only the run of changed paragraphs that `changed_passages` in `tools/new_prose.py` finds, plus the one unchanged paragraph or table row on each side inside the same section. A rewrite licence for the whole section would turn a one-sentence fix in § "Displayed precision" (8,095 words) into an 8,000-word diff, against the design's own cost line, "a few paragraphs". One neighbour each side still lets it fold new text into the paragraph beside it, which is problem 1 above. Decided by this session as a placeholder for the owner to overrule.
2. **The agent file.** `.claude/agents/copy-editor.md` has `tools: Read` and `omitClaudeMd: true`, and no `model` or `effort` line, so it runs on the session's own model and effort. `omitClaudeMd` leaves out `CLAUDE.md` and the project rules (https://code.claude.com/docs/en/sub-agents.md, § "What loads at startup", read 2026-11-04), so the agent does not have `.claude/rules/plain-writing.md`. The file it reads therefore opens with that rule's text. The request names one file to read. The reply format stays "[N] keep" or "[N] rewrite" with a fenced block, so `tools/rejected_prose.py`'s parser still reads it. The prompt drops the length cap and keeps the three cut reasons. Where a passage grew, it asks the copy editor to name the facts the added words carry. The `agents` directory existed when this session started, so a new file there loads without a restart (same page, § "Write subagent files").
3. **Which files it reads.** A changed Markdown or Python file is reviewed when a row of the reader table names it, so the table decides the coverage. The `imports_product` filter is removed. The item-briefs row gains the paths `docs/items/`, `.claude/`, `tools/`, `subprojects/docket/src/`, `CLAUDE.md`, `docs/apparatus.md`, `docs/maintainer.md`, `docs/worker.md`, `docs/resident-instructions.md`, `docs/WORKING_NOTES.md`, `docs/dead-ends.md` and `docs/prose-review/README.md`, and its kind becomes "pull request titles and bodies". YAML front matter is blanked row for row, using `FRONT_MATTER_RE` from `docket.model`, before units, headings and facts are read, because `docket.markdown` otherwise reads it as a setext heading.
4. **Replies and pull request bodies.** `new_prose.py --draft FILE --kind WORDS` prints the rule, the reader rows whose kind cell contains WORDS, and the file as unit 1. `Reader` gains a `kind` field.
5. **The test set.** `tools/rejected_prose.py` hashes the whole agent file as its prompt, and `show` prints the rule where it printed the prompt. `docs/prose-review/prompt.md` is deleted. The two example pairs in `PL-J1ZM` move to `docs/prose-review/examples/`.
