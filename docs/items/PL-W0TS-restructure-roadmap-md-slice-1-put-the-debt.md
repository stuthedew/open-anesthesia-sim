**Problem.** Restructure ROADMAP.md, slice 1: put the debt-gate and development rules and the next release ahead of the shipped milestones, mark v0.6.0 completed, and give the version table, the release-tag rules and each planned milestone a heading

**Source.** The copy editor's structure read of `ROADMAP.md`, run on the project owner's Mac on 2026-11-06: one read per chapter, then one read of all the chapters' outlines together. Row numbers are `ROADMAP.md` at `aff76df1`, the last commit to change it before slice 1 (`PL-W0TS`), so a later slice finds each passage by the words the finding quotes. The project owner chose to file the findings as items and apply them one slice per pull request (project owner, 2026-11-07, ratified, over one pull request for the whole restructure), because the release tools read the roadmap's gate sections and a small move is easier to check against them. The raw reads are in the project's shared folder, `/mnt/project-files/v0.7.0/repo-copy-edit/mac-structure-reads/ROADMAP-md/structure/`.

**Why it matters.** § "The debt gate" and § "Development rules for scientific milestones" define the terms that every milestone section applies, and both come after every milestone section. A reader meets a gate term up to 7,700 rows before its definition. The release being built, v0.7.0, sits behind about 6,400 rows of shipped history. The version table, the release-tag rules and each of the 40 planned milestones have no heading of their own, so the reader cannot find one from the outline.

**What the tools read, checked before this slice.** `docket.roadmap` reads the version table as the first table under the level-2 heading "Versioning decision", the timeline as the first table under the level-3 heading "The timeline", the current version from the level-2 heading "Current baseline: vX.Y.Z", and each milestone from a level-2 heading holding a version, with its level-3 subsections whose titles begin "Debt gate", "Required scope", "Goal", "Definition of done" and "Explicitly out of scope". It sorts the milestones by version, so their order in the file does not matter to it. A level-3 subheading inside "Versioning decision" does not end that section, and a level-3 subheading inside "Planned milestones" is read by nothing.
