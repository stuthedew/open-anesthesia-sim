**Problem.** A reply states a fact marked from memory or not checked, where the owner wants it looked up first and stated with its source

**Asked for by the project owner on 2026-11-11**, in the session working
`PL-RF2S`. That session had written: "From memory, and not checked against
Apple's page, that setting is System Settings → Keyboard → "Keyboard
navigation", off by default." The owner: "why do you do stuff like this where
you explain to me all the ways you didn't look something up and instead was
from memory ... Can you stop? Just look it up." And then: "The looking up
instead of from memory statements should be default behavior for me in all
interactions".

**Why the rule from `PL-6VZF` did not stop it.** `CLAUDE.md` § "Proactive
expert review and domain best practices" says never to cite a source from
memory. The sentence above cited no source. It stated a fact and disclaimed
it, which that rule's wording does not name.

**Done in the same session, as the behaviour-change rule asks.** One sentence
was added to that bullet of `CLAUDE.md`: never state a fact with a note that
it is from memory or was not checked; look it up, then state it with the
source. `docs/resident-instructions.md` § "Never cite a source from memory,
added 2026-11-10" records it. The generator pause does not hold this edit,
because the owner asked for it.

**What is left.** The rule in this repository reaches only sessions that
work here. For every other conversation, the owner adds the same sentence to
their account-wide instructions. The session gave the steps in its reply
(Anthropic's help page "Understanding Claude's personalization features",
https://support.claude.com/en/articles/10185728-understanding-claude-s-personalization-features,
read 2026-11-11). Triage decides whether this item closes on the edit above.

**The owner added the sentence, 2026-11-11.** After the reply with the steps,
the owner wrote to the same session: "added sentance". The session cannot read
the owner's account settings, so the wording that was added is not confirmed
from here. Nothing is left for a session to do on this item.
