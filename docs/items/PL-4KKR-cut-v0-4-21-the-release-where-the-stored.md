**Problem.** Cut v0.4.21: the release where the stored coefficients were
checked against the primary measurement and the specification learned to argue
backwards.

Twenty-one items have finished since v0.4.20 and none has shipped, so
`bin/docket next` and the session-start digest ask every session to offer a
release before taking new work. Two of the twenty-one asked the project owner
outright whether to cut it - `session_01DChZeVWCohKwvKibmWgvmQ` and
`session_01XW1ii46qb6L7JEzrBwHTMo` both closed with the question - and this
session is the answer to them rather than a third independent offer.

**Why it matters.** The twenty-one are three strands rather than a miscellany,
and the release name should say which. The largest is provenance: the project
owner supplied Yasuda, Targ and Eger's 1989 tissue-solubility full text, and
`PL-B9K7` checked all nine stored tissue:gas coefficients against its Table 1 -
every one inside 0.71 SD of the measured mean, three reproducing it to the
stored precision - which is the first time this project's central parameter set
has been compared with the measurement it descends from. `PL-FN5F` took the
decision that follows and split it: the adoption flag moves, the values do not.
`PL-8GJ6` closed because the full text made its question moot, and `PL-LS3H`
quantified what the ideal inert circuit omits from a second paper of the same
authors' same year.

The second strand is `docs/MODEL.md` learning to argue in the other direction.
`PL-BLHV` writes the positive intended-use statement the document never had -
it said only what the tool is *not* - and records IEC 62304 Class C with the
reasoning. `PL-FDBK` adds the first hazard table, each row naming the test that
holds its mitigation, with `check_named_tests` in `tools/doc_check.py` keeping
that column from rotting into decoration.

The third is fourteen apparatus items, nine of which are a command that
asserted something untrue: a commit count for a branch with no commits, a
diff line that had been removed, a checkbox contradicting the figure above it,
a rules block missing the rule, a placeholder a shell read as redirection, a
recovery that deleted the wrong ref, a beat that called a finished milestone
unfinished, a feature survey with no plan placement, and a lane that sent
apparatus work to a simulator session.

Filed before the cut rather than after it, per `CLAUDE.md`'s rule that
repository work taking a commit of its own is filed first: every in-flight
guard this project has matches a `PL-` id, and a release cut has none until
somebody starts one. `PL-66FP` is what the unfiled version cost - two sessions
cut v0.3.7 within the hour and the second was discarded at the merge.
