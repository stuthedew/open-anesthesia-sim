**Problem.** Main carries 59 merge commits whose subjects are branch names
(`Merge pull request #70 from stuthedew/claude/splitting-error-setting-changes-cptjcw`)
and 22 commits whose entire subject is `Close out` or `Record the commit that
carries the work`. Roughly a third of the log is process bookkeeping that means
nothing outside the session that wrote it.

**Split on 2026-08-30.** This item also required a green check before merge.
That is now `PL-J786` (require a green `checks` run before any merge into
main), because it needs no dependency and this half does — bundling them held
the urgent one behind the slower one. `PL-J786` is the safety-relevant half;
this one is about how the history reads.

**Why it matters.** Main's log is what a reader uses to follow how the
simulator was built. Under squash-merge each item lands as exactly one commit,
which folds the `Close out` bookkeeping into the change it belongs to and
removes the merge-commit subjects entirely. Branch names generated by the web
session (`claude/...-cptjcw`) stop entering the permanent history, which is why
they need no separate attention.

Squash is the right granularity here because the queue already forces work into
item-sized units: one item, one pull request, one commit on main. It is also
compatible with the trunk model — releases are marked by tags, of which there
are eight, all on main.

**Where.** GitHub repository settings for `stuthedew/open-anesthesia-sim`. No
files in the tree change.

**Approach.** Two settings:

  - squash-merge as the only permitted merge method, with
    delete-branch-on-merge enabled.
  - the squash commit-message default set explicitly to the pull request title
    and description, so the subject that lands on main has a deterministic
    shape. `PL-ZQ9C`'s check depends on the `(#N)` suffix being there, and the
    default otherwise varies with the number of commits in the pull request.

**Sequencing.** `PL-ZQ9C` (record an item's pull request, so provenance
survives squash-merge) must land first. Under squash-merge with
delete-branch-on-merge, the branch commit an item records in `commit:` never
exists on main and becomes unreachable once the branch is deleted, so every
item closed after this switch would fail `PL-68XK`'s reachability check.

**Not blocked on the account plan.** Unlike `PL-J786`, merge-method and
delete-branch-on-merge are ordinary repository settings, enforced on private
repositories on every plan. This half can land as soon as `PL-ZQ9C` does.

**A consequence worth stating rather than discovering later.** With no
approving review required (see `PL-J786`), the review leaves no
machine-readable trace. Its only visible evidence is a review comment on the
pull request and the `Reviewed-by:` trailer `PL-XH1D` describes, which makes
both worth more than they looked.

**Done when.** Main accepts only squash merges, deletes the head branch on
merge, and composes squash subjects from the pull request title — each
confirmed on a throwaway pull request.

**Unblocked 2026-08-30.** PL-ZQ9C (record an item's pull request, so provenance
survives squash-merge) closed, so the provenance this item would otherwise
break is already carried by the `pr` field rather than by `commit`. The
`blocked-by` line is kept as the record of what it waited on. Still not
delegable: the two settings live in GitHub repository configuration, not in the
tree.
