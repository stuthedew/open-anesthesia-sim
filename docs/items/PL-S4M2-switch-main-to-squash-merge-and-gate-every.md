---
id: PL-S4M2
title: Switch main to squash-merge and gate every merge on a green check
status: untriaged
feature: public-history
added: 2026-08-30
not-delegable: the three settings live in GitHub repository configuration, not in the tree, and no MCP tool in this session exposes branch protection. A session can confirm the result on a test PR but cannot make the change.
---

**Problem.** Nothing gates a merge into main. Across the last twelve pull
requests the median time from open to merge is under two minutes - #64 merged
23 seconds after opening, #71 in 30 - while the `quality` job takes about 50
seconds. #71's check run completed 26 seconds *after* it was merged, and the
pull request carried no review at all. Separately, main carries 59 merge
commits whose subjects are branch names (`Merge pull request #70 from
stuthedew/claude/splitting-error-setting-changes-cptjcw`) and 22 commits whose
entire subject is `Close out` or `Record the commit that carries the work`.

**Why it matters.** Two distinct things, and the first is not cosmetic.
Merging before the checks finish means unverified code reaches main in a
repository whose stated standard is that a displayed value could influence
patient management; the `quality` job is the only automated statement that
the pinned reference states still hold. Second, main's log is what a reader
uses to follow how the simulator was built, and roughly a third of it is
process bookkeeping that means nothing outside the session that wrote it.

**Where.** GitHub repository settings for `stuthedew/open-anesthesia-sim`. No
files in the tree change.

**Approach.** Three settings:

  - squash-merge as the only permitted merge method, with delete-branch-on-merge
    enabled. Each item then lands as exactly one commit on main, which folds
    the `Close out` bookkeeping into the change it belongs to and removes the
    merge-commit subjects entirely. Branch names generated by the web session
    (`claude/...-cptjcw`) stop entering the permanent history, which is why
    they need no further attention.
  - a ruleset on main requiring the `checks` job to pass, with administrators
    included so the rule binds the owner too rather than being bypassable by
    the only person who merges.
  - the squash commit-message default set explicitly to the pull request title
    and description, so the subject that lands on main has a deterministic
    shape. PL-ZQ9C's check depends on the `(#N)` suffix being there, and the
    default otherwise varies with the number of commits in the pull request.

Squash is the right granularity here because the queue already forces work
into item-sized units: one item, one pull request, one commit on main. It is
also compatible with the trunk model - releases are marked by tags, of which
there are eight, all on main.

**Sequencing.** PL-ZQ9C (record an item's pull request, so provenance survives
squash-merge) must land first. Under squash-merge with delete-branch-on-merge,
the branch commit an item records in `commit:` never exists on main and becomes
unreachable once the branch is deleted, so every item closed after this switch
would fail PL-68XK's reachability check.

**Do not require an approving review.** GitHub forbids a pull request's author
from approving it, as a platform rule no setting overrides, and every pull
request in this repository is opened by the project owner. An approval
requirement would therefore lock him out of his own repository, and a rule that
has to be bypassed on every merge trains bypassing rather than review. Require
the check; leave review to happen without a gate enforcing it.

That has a consequence worth stating rather than discovering later: with no
approval recorded, the review leaves no machine-readable trace. Its only
visible evidence is a review comment on the pull request and the `Reviewed-by:`
trailer PL-XH1D describes, which makes both worth more than they looked.

**Done when.** Main accepts only squash merges, deletes the head branch on
merge, refuses a merge without a passing `checks` run including for
administrators, and composes squash subjects from the pull request title - each
confirmed on a throwaway pull request.
