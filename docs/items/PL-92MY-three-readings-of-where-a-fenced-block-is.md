**Problem.** Three readings of where a fenced block is disagree: docket checks._without_fences follows CommonMark (a backtick opener's info string holds no backtick, and only a closed block is blanked), docket instructions.FENCE_RE toggles on any line opening with three backticks or tildes, and doc_check._without_fences toggles on backtick lines and blanks everything after one left open

Found 2026-09-26 building `PL-NQ3X` under `PL-GPJ7`'s step 3, which needed a fence reader for item briefs and could reuse neither: `instructions.FENCE_RE` reads `PL-6SRZ`'s wrapped triple-backtick code span (its line 39) as an opening fence, so a later real fence would close it and blank the headings between. The three disagree on exactly that line, on tildes, and on a fence left open. doc_check's reading is live: it opens a fence at that line and nothing closes it, so the rest of `PL-6SRZ`'s brief is never read for line citations. A shared reader in `docket`, which `tools/doc_check.py` already imports from, would give one answer; which of the three behaviours it keeps for an unclosed fence is the open part, since doc_check's blanking of everything after one is CommonMark's rendering and checks' reading-as-written avoids reporting a visible section as missing. Possibly a member of `PL-PVW2`'s fact (a predicate spelled again wherever it is needed); for triage to decide.

**Reproduced 2026-09-26 at `dae71d76`.** With a line citation of `tools/doc_check.py` past its last line appended to the end of `PL-6SRZ`'s brief, `python3 tools/doc_check.py check` exited 0 and named nothing; the same citation written just above the wrapped code span was reported. There are five spellings, not three: `tools/doc_check.py` also reads fences through `FENCE_RE` (column zero, backticks only, behind `_fenced_blocks`) and `ANY_FENCE_RE` (a toggle, in `check_prose_provenance` and `_without_code`). Compared over the 1,802 markdown files the two tools read - the standing documents, the rules and skills, and every item - the spellings disagree on no other line, and no fence is left open under CommonMark's reading. `FENCE_RE` differs only on indented fences in item briefs, which its two readers, the package map and `make` mentions, never read.

**Why it matters.** `make check` reports that the citations in the live briefs resolve while `PL-6SRZ`'s brief goes unread below the span: a partial reading handed over as a complete one, which `.claude/rules/apparatus-standard.md` § "The floor: an answer has to be true, or has to say it could not answer" refuses. The same line in an instruction file would hide every date below it from the dated-assertion audit, in `docs/MODEL.md` every provenance marker below it from `check_prose_provenance`, and anywhere every math delimiter below it from `_without_code`. And the next reader copies whichever spelling it meets first, as `PL-NQ3X`'s build nearly did.

**Done when.** One module in `docket`, `fences.py`, answers where a fenced block is, by CommonMark's rules: three or more backticks or tildes at any indentation open one, a backtick opener's info string holds no backtick, and a bare run of the same character at least as long closes it. `checks`'s brief sections, `instructions.parse`, and `tools/doc_check.py`'s `_without_fences` (and with it `tools/possessive_section_check.py`), `_fenced_blocks`, `check_prose_provenance` and `_without_code` all read through it, and no other fence pattern is left in `docket` or `tools/`, apart from `subprojects/docket/tools/migrate_from_punch_list.py`, a finished one-off migration. `subprojects/docket/tests/test_fences.py` pins the reading, and `tests/unit/test_doc_check.py` pins the case that broke: a line citation below a line-initial triple-backtick code span in a live brief is reported.

**A fence nothing closes is not a fence** (decided at triage, 2026-09-26: a session's call under rule 14 of `.claude/rules/instruction-writing.md`, since its blast radius is how two apparatus tools read a document that is already broken). The opener and every line after it are read as written, which is `checks`'s reading today. CommonMark runs the block to the end of the document instead, and every reader here that skips literals would then skip the rest of the file silently, which is the defect this item found; reading it as written costs at worst a loud false error on a literal, repaired by closing the fence the document needs anyway. The residual is the other side: an unclosed fence's lines are not read as a package map or as fenced `make` commands. The package-map check already errors when it finds no tree, and no file in the tree has an unclosed fence, so reporting one would be a new check, which the generator pause holds and nothing measured would pay for.

**Design, for the build.**

- `docket/fences.py`: `OPEN_RE` and `CLOSE_RE`, moved from `checks`; `Block(start, end)`, the 0-based indices of a closed block's two fence lines; `blocks(text)`, every closed block in order; `fenced_lines(text)`, every line of one, both fence lines included; and `without_fences(text)`, each such line blanked to spaces with its own terminator kept. The terminator is what `str.splitlines()` cut, so a form feed or U+2028 is not blanked into the line and every later line number still holds.
- `checks`: `FENCE_OPEN_RE`, `FENCE_CLOSE_RE`, `_blank` and `_without_fences` go; `_sections` and `_stub_above_brief` call `fences.without_fences`.
- `instructions`: `FENCE_RE` goes, and its reasoning for skipping a dated example moves to `parse`, which skips `fenced_lines`.
- `tools/doc_check.py`: `FENCE_RE`, `INDENTED_FENCE_RE`, `ANY_FENCE_RE` and `_without_fences` go. `_fenced_blocks` yields each block's opening line number and the lines between its fences; `check_prose_provenance` skips `fenced_lines`; `_without_code` keeps its order, popping list containers and testing for an indented code block before any fence, and swaps its toggle for the block opening on the line, blanked through that block's closing line.
- `tools/possessive_section_check.py` calls `doc_check.without_fences`, and `.claude/rules/citation-drift.md`'s sentence naming `_without_fences` names the docket function.
