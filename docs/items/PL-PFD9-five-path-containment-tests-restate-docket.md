**Problem.** Five path-containment tests restate docket.model.is_under: checks's _inside, verify's _within, workflow_paths_check's is_covered and two prefix loops in vcs

**Sites**, from `PL-KGYT`'s sweep (its `**Swept 2026-10-01.**` line), each read against the source that day. Where a line says *agree*, the two spellings answer alike on every input today, and the risk is the next change to the fact reaching one of them only. `subprojects/docket/src/docket/checks.py:1091` (`_inside`), `subprojects/docket/src/docket/verify.py:1600` (`_within`), `tools/workflow_paths_check.py:186` (`is_covered`), and `subprojects/docket/src/docket/vcs.py:3162` and `:3257`. The sweep reported inputs on which `checks.py`'s and `vcs.py`'s answer differently (a root written with a trailing slash; a `touches` entry with a leading slash), not confirmed here.

**Searched 2026-10-03, before the work.** An `ast` walk of `subprojects/docket/src`, `subprojects/docket/tools`, `tools/`, `.claude/hooks/` and `.github/` for every `startswith` or `removeprefix` given a string ending in `/`, and every `relative_to`, plus a grep for prefixes built by hand, found one more site of this fact: `tools/workflow_paths_check.py`'s `unplaced_ancestor`, which normalized each entry as `is_under` does and tested it against `prefix + "/"`. It runs only for a file neither list covers, so no entry can equal the prefix, and it agrees with `is_under(entry, (prefix,))` on every input it receives. Left, each a different question: the twelve reads that build the store's or the notes directory's prefix from `items_dir` or `notes_dir` by hand (`arming.py` two, `claims.py` three, `vcs.py` six, `checks._declared_item_file`), which test git's paths against where the store lives, slice a file name out by it or hand it to git - a different fact from `is_under`'s, and one `is_under` cannot answer, since it keeps a leading `./`. Reconsidered at the project owner's request, they are filed rather than left: `items_dir = "./docs/items"` reads the store, because `root / items_dir` collapses the dot, while their prefix matches no git path, so `PL-F66M` normalizes both settings once at config load; `doc_check.py`'s three and `generator_check.py`'s one, which test git's own output against a module constant no writer types; `model.covers` and the equality tests in `concurrency.py` and `generator_check.py`, which are symmetric; and the `relative_to` calls, which turn a path under a known root into a relative one.

**Why it matters.** Each site answers from its own spelling of a fact docket exports, so the next change to that fact reaches the export and not the copy, and the two then answer differently with nothing to say so - the mechanism `PL-KGYT` closed as spent.

**Done when.** Each site under **Sites** reads the export instead of its own spelling, and where a site answered differently from the export, a test pins that input.

**Generator check.** A member of `PL-KGYT` (done 2026-10-01), filed by that head's closing sweep and named in its `root-cause-of:`; its fix, the write-time rule in `.claude/rules/apparatus-standard.md` (`PL-HC8P`), covers new readers and these predate it, so this is neither a post-close instance nor a new generator.

**Done, 2026-10-03.** All six sites read `docket.model.is_under`: `checks.py`'s three pytest-target tests (`_inside` deleted, and its two callers typed `tuple[str, ...]` to match), `verify.py`'s seven (`_within` deleted - it was `is_under`'s body line for line), `vcs.since_filed` and `vcs.gone_paths`, and `tools/workflow_paths_check.py`, which now imports it as `tools/` imports `docket` elsewhere (`tests/unit/test_tools_portability.py`'s `VENDORED`). Its `is_covered` and the test that pinned it to `is_under`, `test_the_prefix_comparison_agrees_with_the_lane_it_mirrors`, are deleted, there being no second copy left to drift, so `docket verify --self` reports that test's assertion as removed. Measured against the old spellings: `checks.py`'s answered differently for a tree declared with a trailing slash - `collected_test_paths = ["tests/"]` compared every target with `tests//`, which switched the redundant-pytest and `-k` refusals off for every run naming a path - and two tests in `subprojects/docket/tests/test_checks.py` pin it, both failing on the old `_inside`. The sweep's other input, a `touches` entry with a leading slash, never reaches either `vcs` loop: git refuses the pathspec (`fatal: Invalid path '/tools'`, exit 128, git 2.43.0, 2026-10-03), so both reads report themselves unread first. Two inputs now read differently and neither is pinned, because neither is written here: a git path with leading or trailing whitespace, which `is_under` strips in `vcs` as `verify.py` already did (no tracked path has one), and a pytest target written as an absolute path, `/tests/x.py`, now read as under `tests` (no `verify:` command in the store names one). On this tree, `docket check`, `docket show` for six items and `tools/workflow_paths_check.py` print the same with the old code and the new.
